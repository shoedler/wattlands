# Decisions: vendoring (W0)

- 2026-10-21. Decision: vendor GUT 9.7.1 from the `v9.7.1` tag's source archive (commit `aeb5d4f3f7f0a6c9b5e178876d6c99b791fda605`), all of `addons/gut/` unchanged. Alternatives: the Asset Library, or a newer GUT from `main`. Reason: BRIEF 1 asks for pinned GitHub sources and BRIEF 7 names 9.7.1, the release for Godot 4.7.x. The vendored tree hash equals upstream's (`5d68938`), so the copy is verifiably unmodified.
- 2026-10-21. Decision: pin GDBLE to the tagged release v0.6.0 (`gdble-v0.6.0.zip`, tag commit `ecae959`, built from `690a833`). Alternatives: main at `13c49c7`, or v0.5.5 with the double first import. Reason: BRIEF 4.2 prefers a tagged release at or after `13c49c7` over main, and v0.5.5 aborts Godot 4.7.2's first headless import. v0.6.0 contains `13c49c7`, ships `BUILD_INFO.json` with `release_ready: true`, and its asset digest and `SHA256SUMS` verify. The first headless import on a fresh `.godot` cache exits 0 (see the import-check entry below).
- 2026-10-21. Decision: keep only the Windows x86_64 and Linux x86_64 GDBLE libraries; drop the macOS dylibs (8.6 MB), the Android AARs (3.0 MB), `gdble.gdap` and `permission_startup.gd`, and remove their `.gdextension` entries and `android_aar_plugin`. Alternatives: keep the whole release (21 MB). Reason: Windows is the target and CI runs on Linux; the rest would add 11.6 MB of binaries no target uses, and `.gdextension` entries for missing files would only fail later. Hashes of everything removed are in `docs/deps.d/gdble.md`.
- 2026-10-21. Decision: set `reloadable = false` in `addons/gdble/gdble.gdextension`. Alternatives: upstream's `true`. Reason: BRIEF 4.2; hot reload of a BLE extension would drop the trainer session.
- 2026-10-21. Decision: drop upstream's `addons/gdble/SHA256SUMS` and reproduce it verbatim in `docs/deps.d/gdble.md`. Alternatives: keep it in the addon. Reason: after the platform trim and the `.gdextension` edit it no longer verifies, and a failing checksum file in the tree would mislead; the record keeps the provenance.
- 2026-10-21. Decision: keep upstream's `README_EN.md` and `docs/API_CONTRACT.md` under `addons/gdble/docs/`. Alternatives: rely on GitHub. Reason: the ble module codes against them offline (event timing, `connect_device()` being a factory, no auto-reconnect); Godot does not import `.md` files.
- 2026-10-21. Decision: keep GDBLE v0.6.0 after the import check. On Godot 4.7.2 (.NET build) the first headless import of the main checkout on a fresh `.godot` cache exits 0 in about 4 s, with no error lines, and both classes load (`BluetoothManager`, `BleDevice`). Alternatives: main's prebuilt addon at `13c49c7` or later, or v0.5.5 with BRIEF 4.2's double import. Reason: neither fallback is needed. Two more imports (incremental, and fresh again) also exit 0 and change nothing. Logs: `build/vendor/import1.log`, `import2.log`, `import3_fresh.log`.
- 2026-10-21. Decision: commit `addons/gdble/gdble.gdextension.uid` (`uid://daj40y0ysg0l8`, written by the first import) as the addon's only added file; the `addons/gdble` tree to commit is `b9f97530f34f35c7290e35d06ed996b40ba1d78f`. Alternatives: delete it, or gitignore it. Reason: BRIEF 2 commits `*.uid`; without it every fresh clone writes a different random UID. Godot keeps it stable on later imports.
- 2026-10-21. Decision: record that `addons/gut/` stays byte-identical to upstream through imports and test runs (tree `5d68938`, no new `.uid` or `.import`), so it needs no local modification entry. Alternatives: none. Reason: checked by hashing the working copy after three imports and four GUT runs.
- 2026-10-21. Decision: the GDBLE surface to code against is the verified ClassDB list in `docs/deps.d/gdble.md`. Every member BRIEF 4.2 lists exists with the same argument count; action methods return an `int` operation id; the rest is additive. `BleDevice.disconnect()` and `BleDevice.is_connected()` clash with `Object.disconnect(signal, callable)` and `Object.is_connected(signal, callable)`, so on a `RefCounted`-typed device they must be called as `call(&"disconnect")` and `call(&"is_connected")`. Alternatives: hold devices untyped. Reason: a probe showed the direct calls are parse errors on `RefCounted` or `Object` variables ("Too few arguments ... Expected at least 2"), the `call()` forms compile and reach GDBLE's methods, and CLAUDE.md keeps static typing (`Object`/`Node`/`RefCounted`) for GDBLE objects.
- 2026-10-21. Decision: `tools/run_tests` must not trust GUT's exit code for an empty run. Alternatives: rely on the exit code. Reason: with no tests GUT 9.7.1 prints `[GUT ERROR]:  Nothing was run.`, prints no "Run Summary" and exits 0, writing a JUnit file with `tests="0"`. The gate's string and JUnit checks (BRIEF 7) catch it; the real logs were run through `tools/lib/gut_gate.mjs` to confirm.
