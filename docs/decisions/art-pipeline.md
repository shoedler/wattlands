# Decisions: art pipeline (`tools/art`, `tests/art`, `docs/ART_PIPELINE.md`)

Short ADRs for BRIEF 3.10. "fal docs" means fal's public model and platform API pages, read (never called with a key) on 2026-10-21.

- **2026-10-21: Request size = nearest aspect, about 1 MP, within the base price.** Among sizes valid for fal (16 px multiples, 655,360 to 8,294,400 px, 3840 px edge, 3:1), `generate.mjs` picks the smallest aspect error, then (within 0.05 %) the size nearest 1,048,576 px, never above 1536 × 864 worth of pixels unless nothing fits. *Alternatives:* always the minimum pixel count; always the maximum. *Reason:* every sprite between 1:3 and 3:1 lands within 1 % of its aspect (Tank checks 2 %, Fishing 5 %) at the $0.07 base price, with enough resolution for area averaging. Beyond 3:1 the request is 3:1 and `--dry-run` lists it; `tile: true` makes that the intended segment.
- **2026-10-21: Endpoint limits from fal docs.** Both GPT Image 2.5 endpoints state 16 px multiples, a 3840 px edge, 3:1 and 655,360–8,294,400 px; `endpoints.json` keeps BRIEF's 3840 px / 3:1 fallback in `defaults` for endpoints that don't. `mock_fal` checks fal's limits independently, so a wrong `endpoints.json` fails the tests with a 422.
- **2026-10-21: Prices.** Sunburst high is $0.07 up to 1536 × 864 and scales by pixel count above (BRIEF). Low and medium are priced as high (never under it); xhigh, max and auto (which may reach max) scale by flare's listed quality ratios. Flare uses its listed per-size table: the dearest row up to the smallest row that holds the request, plus $0.002 of prompt text. Money is summed in integer $0.0001 units. *Reason:* conservative estimates never let the budget stop undercount.
- **2026-10-21: Billed amounts.** fal documents no per-request cost in the queue, result or history responses (its usage API is aggregated and needs billing permissions). `generate.mjs` records a billed amount only when a response carries `cost_total` at the top level or under `billing` or `metrics`; `mock_fal` reports it under `billing` when configured. The spend total and the budget stop take max(estimate, billed) per request. *Alternative:* poll the usage API with request tags. *Reason:* delayed, needs extra key permissions, and can't attribute single requests.
- **2026-10-21: Free paths before paying.** Per sprite (unless `--reroll`): the local cache for the identical endpoint and input; a stored image URL, or resuming an unfinished request from its stored `status_url`; then fal's history (`/v1/models/requests/by-endpoint?expand=payloads&status=success&start=<now − 24 h>`, following `next_cursor`), matching every field of our input against `json_input`. A history that can't be read is a warning, then the run pays. *Reason:* BRIEF's recovery after a failed download, plus crashes between submit and manifest write; never blocking art on a missing `models:requests:read` permission.
- **2026-10-21: Statuses and spend.** A request fal accepted counts as paid even if it later fails (`failed`, `timeout`, `download_failed`); a `submit_failed` (no request id) does not. Submits are never retried automatically (a retry could pay twice; the history lookup finds a submit that did succeed). Status polls tolerate 5 consecutive errors; downloads are tried 3 times.
- **2026-10-21: Budget stop.** Workers take sprites in art.json order; each reserves its estimate before submitting and adds any billed excess when known. The first sprite that would pass `--budget` stops all further payment (free paths continue), its id and the rest are listed, and the run exits 3. With `--concurrency=1` the paid set is fully deterministic. Default concurrency 4. *Reason:* "halts before the run's estimated spend would pass" read literally; a cheaper later sprite does not sneak in after a stop.
- **2026-10-21: Selection.** Each run selects, per processed sprite, the result for its current input (new, recovered or cached), so the newest wins by default and returning to an earlier input re-selects its cached result. "Newest" is the newest request: free paths are tried newest request first, so a paid result newer than the cached one (a `--reroll` whose download failed) is recovered and selected instead of the older cached result; an unfinished newer request gets a single status check, not a full wait, when a cached result exists. `--select` marks a result `selected_by: "user"`; a cache-only run keeps that choice, a new or recovered result replaces it, and re-fetching an image that was already `ok` (after a cache wipe) does not count as new. A `--select` choice whose raw image is missing is fetched again from its stored URL by the next run that includes the sprite. `--select` edits only the manifest and can't be combined with `--only`, `--reroll` or `--dry-run`. *Reason:* Tank's flare-then-sunburst flow and Fishing's keep-the-draft flow both work without extra flags.
- **2026-10-21: The art lock and hosts.** The lock is checked right after argument parsing, before any file or socket. `--mock` must be a loopback URL; in mock mode `FAL_KEY` is never read and requests carry `Authorization: Key mock`. Real mode contacts only https `*.fal.run`, `*.fal.ai`, `*.fal.media`, sends the key only to `queue.fal.run` and `api.fal.ai`, follows redirects by hand (GET only, at most 3, re-checking the host), and redacts the key and each `:`-separated part of it from every message. The source never names the network lock variable (a test scans for it). When the client refuses to fetch a result image (a host outside that list), the run stops paying at once (no download retries, no further submits, exit 1): fal bills on completion, so every further sprite would be money spent on an image the tool may not fetch. *Alternative:* allow the image's host. *Reason:* BRIEF 3.10 allows only fal's hosts; a human decides whether to widen the list.
- **2026-10-21: Tests never set `WATTLANDS_ALLOW_ART`.** BRIEF 7.1 asks every child to run without it, and `test/helpers.mjs` `runGenerate()` enforces the rest: every child gets `--mock`, except refusal cases, which must run under a preload that makes `net`, `tls`, `http(s)`, `dns` and `fetch` throw and log (the "refusal before any socket" test). The "permission set, no key" refusal and `--dry-run`/`--select` without `--mock` run `main()` in the test process with a plain env object (never `process.env`) and a `fetch` that throws and records; the real-mode transport (auth hosts, allowlist, redaction) is tested on `FalClient` with an injected fetch and a dummy key passed in code.
- **2026-10-21: Exit codes.** 0 done, 1 some sprites failed, 2 usage or art.json error, 3 budget stop, 4 art lock refusal. Failures win over a budget stop.
- **2026-10-21: art.json is strict.** Unknown keys are errors (except `notes` and keys starting with `_`), ids and part names are `[a-z0-9]` words joined by single underscores, `mirror` needs `tile`, and every problem is listed at once. `anchor` defaults to the sprite's `align`; named anchors use the align names. *Reason:* a typo such as `backround` would otherwise silently generate the wrong art and cost money.
- **2026-10-21: Pixelation maths.** Trim at alpha ≥ 16/255; area averaging with exact fractional coverage, separable, premultiplied alpha, in sRGB-encoded values (dark outlines stay dark); alpha ≥ 0.5 becomes opaque, everything else `(0, 0, 0, 0)`; quantization to the nearest palette color in Oklab (Ottosson's matrices), ties to the lower index; optional 4×4 Bayer dither (±16 sRGB units) before quantizing. Fit offsets: left/top flush at 0, right/bottom flush at the edge, centre rounded to a whole pixel. A tile strip is assembled at source resolution (segments butt together, every second one flipped with `mirror`) and then resampled once. *Alternatives:* `Image.resize` (not area averaging); linear-light averaging (thins dark outlines). *Reason:* exact, deterministic and fast enough in GDScript (a 1 MP result takes well under a second).
- **2026-10-21: Outputs.** Parts are written as `<sprite id>__<part>.png` (the id rule forbids `__`, so names can't collide), plus `sprites/sprites.json` with every sprite's size, anchor (art pixels), parts and source request; files are rewritten only when their bytes change. Part files of a processed sprite that `art.json` no longer lists are removed (a stale part in an old palette would fail a game's palette-only test); nothing else in `sprites/` is ever deleted. Pixelate warns, and still proceeds, when the selected result's endpoint, prompt or background differs from `art.json`. *Alternative:* refuse such results. *Reason:* Fishing keeps flare drafts on purpose; Tank needs to notice a draft still selected after the sunburst switch.
- **2026-10-21: Pixel import preset (switchable, for W2).** `docs/OWNERSHIP.md` C36 relies on `project.godot`'s `[importer_defaults]` (lossless, no mipmaps), which already holds. As the W1 task asked, `ArtPixelate.apply_import_preset()` also writes a minimal `.import` with the preset (`compress/mode=0`, `mipmaps/generate=false`, ...) next to each PNG that has none, and corrects only those keys in an existing one, keeping its uid. Godot completes the minimal file on import (checked: `tests/art/fixtures/import/`). W2 switches by setting `ArtPixelate.import_preset_mode = IMPORT_PROJECT_DEFAULTS` (no files) or pointing `apply_import_preset()` at world-kits' `PixelImportPreset`.
- **2026-10-21: The end-to-end check is a Node script outside `node --test`.** `tools/art/pixelate_e2e.mjs` runs `generate.mjs` against the mock and then `pixelate.gd` through the wrapper, twice. It is not under `tools/art/test/` because `node --test` there must not start Godot (BRIEF 7: no Godot from inside another test process, and the node suite runs without Godot in CI). The lead can add it as a `tools/run_tests` step after GUT.
- **2026-10-21 (W2): Pixel import preset = project importer defaults only.** `ArtPixelate.import_preset_mode` now defaults to `IMPORT_PROJECT_DEFAULTS`: pixelate writes plain PNGs and no `.import` files, and `run_game()` first checks `PixelImportPreset.check_project_defaults()` (world-kits) and stops with an error if `project.godot`'s `[importer_defaults] texture` lost `compress/mode` 0 or `mipmaps/generate` false. `IMPORT_WRITE_FILE` stays as an opt-in for a folder that must pin the preset; nothing uses it by default. *Alternatives:* keep writing hand-made `.import` files (two mechanisms that can disagree); point pixelate at `PixelImportPreset.write_import_file()` (still per-file). *Reason:* OWNERSHIP C36 names one mechanism, the lead's importer defaults; world-kits' preset needs nothing more for 2D sprites (its recommended `detect_3d/compress_to` only matters for textures used in 3D, which no game does), and the check makes a lost default fail loudly instead of silently importing mipmapped sprites.
- **2026-10-21 (W4): Everything written is redacted; the key is trimmed (W3 ART-W3-1, ART-W3-2).** `saveManifest()` takes the run's redactor and runs it over the whole file text, and the `.art_cache` result JSON goes through it too, so nothing fal sends back (a job error, a result body, an image URL) can carry the key into a committed file. `main()` uses `FAL_KEY` trimmed, the way `fetch` sends it, and `makeRedactor()` also knows the trimmed key and its trimmed `:`-parts. Tested by running `main()` in real mode in a child process under the no-network preload against a fake fal that echoes the header (`test/key_echo.test.mjs`, `test/helpers/key_echo_run.mjs`); the child's environment never has `FAL_KEY` or `WATTLANDS_ALLOW_ART`, and `main()` gets a plain env object. *Alternative:* redact each field that came from fal (easy to miss one).
- **2026-10-21 (W4): A submit whose answer was lost keeps its budget share (W3 ART-W3-3).** Only a submit error that proves fal took nothing (an HTTP 4xx or 5xx answer, or the client refusing to send) releases the sprite's share and is `submit_failed`. A dropped connection, a timeout or an unreadable 2xx body is `submit_unconfirmed`: `paid: true` with no request id, counted in `spend.total_usd` on its own, and the next run adopts it when fal's request history shows a request with the same input (it then gets that request id and counts once). *Alternative:* look the request up in the history at once (the job may not have finished). *Reason:* BRIEF 3.10 "stops before the run's estimated spend passes --budget"; fal bills a queued job when it completes. If fal never queued it, the manifest over-counts one estimate, which stays on the safe side.
- **2026-10-21 (W4): An unusable --select choice gives way (W3 ART-W3-4).** A run keeps a `--select` choice only while its status is `ok`; one that could not be fetched again gives way to the usable result the run has, with a warning naming both. *Reason:* the documented invariant (exactly one usable selected row per sprite); a stale choice made pixelate skip the sprite for good.
- **2026-10-21 (W4r2): A submit that never left is not money spent, and the run stops submitting (W4r2 R24).** `FalClient` records the transport error code on `FalError` (undici's `cause.code`, or the first inner error of an `AggregateError`) and `notSent` when that code proves the request never left this machine: no connection (`ECONNREFUSED`, `ENOTFOUND`, `EAI_AGAIN`, `UND_ERR_CONNECT_TIMEOUT`, unreachable network or host) or a failed TLS handshake (certificate errors, `ERR_SSL_*`; HTTP goes out only after the handshake). Such a submit is `submit_failed` with its budget share released, like an HTTP error, and the run stops submitting (`netStop`, exit 1, the unsubmitted sprites named): the next submits would fail the same way. A reset, a closed socket or a timeout after connecting stays `submit_unconfirmed` (ART-W3-3). *Alternative:* stop after any transport failure (a single flaky reset would end a long run). *Reason:* an offline run marked every sprite paid for good, since fal's history never had them, and `spend.total_usd` (which the game briefs subtract from their caps) over-counted.
- **2026-10-21 (W4r2): A demoted --select choice is fetched again and selected (W4r2 R25).** When a `--select` choice gives way because its image could not be fetched (ART-W3-4), the row keeps `"reselect": true`; every later run that includes the sprite fetches its stored image URL again for free and selects it (`selected_by: "user"`) once that works. `--select` also accepts a paid result whose image is not fetched yet (`download_failed`, or another recoverable status, with an image URL): it is marked `reselect` and the current usable selection stays until a run fetches it. A user's `--select` of a usable row, or a new or recovered result for the sprite, drops any waiting choice. *Alternatives:* select a `download_failed` row at once (pixelate would have no usable result meanwhile). *Reason:* the warning and the docs told the user to `--select` the old result again, which `--select` refused and no run made possible.
