# Decisions: trainer-control (SafetyGovernor, TrainerController, VirtualGears, CadenceEstimator, the 4.6.11 scan)

Short ADRs for `addons/wattlands/trainer/control/`, `tests/governor/`, `tests/control/` and `tests/arch/test_no_bypass.gd` (BRIEF 4.5, 4.6, 7.1).

- **2026-10-21: The controller owns slew, the switch entries and coalescing; the governor owns every other rule.** Each tick the governor computes the governed ERG target (every 4.6 rule except slew) or the stacked SIM state and hands it to `TrainerController.command_erg` / `command_sim`; the controller slews increases at 30 W/s (decreases at once), runs the ramped ERG <-> SIM sequences and decides when to write. *Alternatives:* slew in the governor. *Reason:* BRIEF 4.1 lists slew under the controller and 4.6.12 applies it last; the SIM -> ERG entry must start slewing only once ERG is actually written, which only the controller knows.
- **2026-10-21: Coalescing is one write per 0.5 s slot, computed from the newest command when the slot opens.** Superseded commands are never written, the newest is always sent, and an unchanged state (SIM compared at FTMS resolution: grade 0.01 %, wind 0.001 m/s, crr 0.0001, cw 0.01) writes nothing. *Alternatives:* a sliding 2-per-second window (allows bursts). *Reason:* even spacing suits the KICKR's one-in-flight control point. `status.applied_target_w` is the slewed target, at most one slot ahead of the trainer.
- **2026-10-21: Panic and shutdown write at once, bypassing the slot.** `emergency_safe()` sends SIM grade 0 and wind 0 in the call; `shutdown()` sends SIM flat, then Stop (0x08 0x01), back to back. *Alternative:* wait for the slot. *Reason:* 4.6.5 says "immediately"; safety outranks the write rate. The next ordinary write still waits 0.5 s after them. A trainer bound with `setup()` while panic holds gets the SIM flat write at once.
- **2026-10-21: Ramped switches (4.5) exactly as written.** ERG -> SIM: ERG at max(floor, min(applied target, 3 s power)) when that is below the written target, then SIM grade 0 / wind 0, then the stacked state, each in its own slot. SIM -> ERG: SIM grade 0 / wind 0 when not already flat, then ERG at max(floor, min(3 s power, governed target)), then slew. The first ERG command after connecting uses the same entry (the trainer was left at SIM flat by the connection flow); after a panic resume the entry is the floor (W0 stub doc). The 3 s power is the time-weighted mean of the samples of the last 3 s, each held until the next; `setup()` clears it, so a reconnect enters from the floor.
- **2026-10-21: Samples take effect on the next tick.** `on_sample` queues; `tick` advances platform time first and then processes the queue at that time. *Reason:* with LocalRider's order (device.tick, on_sample, governor.tick) every rule is timed from the tick in which the sample arrived, which makes "3 s (+1 tick)" and "10 s (+1 tick)" exact in tests.
- **2026-10-21: not_pedaling counts an absent cadence as low.** `power < 15 W and (no cadence or cadence < 20 rpm)`. *Reason:* a trainer with no cadence and 3 W is not being pedaled; a rider producing >= 15 W is pedaling whatever the cadence field says.
- **2026-10-21: Rescue triggers are timed while armed.** Cadence < 45 rpm for 3 s or power < 75 % of the applied target for 5 s must hold for the whole window while rescue is armed (in ERG, not paused, governed target >= 60 % FTP after the unverified factor and the 4.6.1 caps, before the warm-up cap and slew); the window starts at the later of the first qualifying sample and the moment rescue armed. "Applied target" for the power test is the target last written to the trainer. *Alternatives:* timers independent of arming (a 70 %-compliant rider coming out of a 50 % recovery would be rescued on the first tick of the next interval); the slewed target (a few watts ahead of the trainer). *Reason:* the most literal reading of "in ERG with ... if ... for 3 s", and no carry-over of a power test made against another phase's target.
- **2026-10-21 (hardening review): Rescue arms on whole watts.** Rescue is armed when the whole-watt governed target is at least floor(60 % FTP), the same whole-watt comparison 4.6.1 uses for the caps and the duration counters. At FTP 201 a 60 % target governs to 120 W (60 % FTP is 120.6 W) and arms rescue; a 59.5 % target (119 W) does not. *Alternative:* compare against the exact 120.6 W, which left a target written at exactly 60 % unarmed at most FTPs. *Reason:* a target exactly at a threshold behaves as at it (4.6.1), and arming errs on the protective side.
- **2026-10-21: Rescue details.** The rescue target is min(governed target, 50 % FTP) (it never raises a lower target), then the floor; the hold ends when cadence >= 70 rpm for 3 s from the first such sample, which emits `rescue_changed(false)` and starts a linear 10 s ramp from 50 % to the channel's current governed value (slew still applies); a SIM phase ends rescue at once (SIM load is self-selected); a new trigger during the ramp restarts the hold. In the ramp_test profile the trigger ends the test (`test_ended`, signal `ramp_test_ended`): 50 % stands until the next `set_plan`, never ramping back.
- **2026-10-21: Warm-up runs on platform time from the first pedaling sample.** It counts 300 s of elapsed platform time from the first sample that is not not_pedaling, and resets once no pedaling sample has arrived for 1200 s. It survives `setup()` (a BLE reconnect does not restart it). Before the first stroke it is active and pending (`warmup_remaining_s` 300). The SIM clamp -2..+3 % applies to the total grade.
- **2026-10-21: Duration limits use the controller's applied ERG target on platform time.** A tick counts above 105 % / 120 % when the whole-watt applied target is above floor(105 % / 120 % FTP); the reset run counts ticks with the applied target <= 90 % FTP in ERG and resets both counters and latches at 120.0 s inclusive; any tick not in ERG (SIM, panic, a switch in progress) restarts the run and adds nothing. The latch takes effect from the next tick, so the time above is exactly 300 s / 60 s.
- **2026-10-21: Directive validation: whole-request refusals and haptic drops.** No phase, the cool-down, bad fields (unknown mode, non-finite values, negative duration, more than one target field, nothing set), `erg_in_sim_phase` (mode ERG or an ERG target in a SIM phase), `haptic_in_erg` (a haptic to a rider not in a SIM phase or block, even with a valid block request: never a mode switch), `outside_range_pct`, SIM block length / unsafe / spacing and `mode_grade_outside_sim` refuse the whole request. A haptic dropped for opt-out, warm-up or cooldown is listed in `record.dropped` and the rest of the request applies; with nothing else set the request is refused with that reason. *Reason:* Siege S10 needs "no dropped channel" as a separate notion from refusal. `haptic_in_erg` refuses the whole request rather than dropping only the haptic because games send haptics as `{mode: SIM, haptic, duration_s}` (T2.7, F2.7): dropping only the haptic would let such a request with a 10-30 s duration open a SIM block for an ERG rider, which is exactly the "haptic turned into a mode switch" 4.6.6 forbids. Opting out (`configure({haptics_on: false})`) also ends a running haptic at once.
- **2026-10-21: Channel details.** `mode: SIM` while a block runs (or in a SIM phase) confirms without changing the block's expiry, so a block can never be extended past 30 s. `mode: ERG` in an ERG phase ends a running block (the exempt closing switch) or confirms. The end of a SIM block takes its mode grade and haptic with it. A factors request replaces the whole `crr`/`cw` channel (an unset factor goes back to 1.0). Expiry counts game time snapped to whole ticks; `duration_s` 0 holds until the phase ends; every channel resets at `start_phase` and `set_plan`. Switch spacing is measured on platform time from the last ERG <-> SIM change of the governor's mode, plan phases and panic included.
- **2026-10-21: Haptic bounds.** Grade x intensity bounded to -3..+3 % (positive bound from 4.6.6, the symmetric negative bound to keep haptics small); duration min(duration_s, 8 s) in game time with a hard 8 s platform-time cap, so a pause can never stretch a haptic; a new haptic while one is active, or within 15 s (platform time) of the end of the last applied one, is a cooldown drop. Haptic wind x intensity is bounded so that cw x ((v + w)^2 - v^2) stays within the force of +3 % grade minus what the haptic grade already used, at the latest reported speed (20 m/s assumed when unknown, the conservative case); grade and wind share one +3 % budget. `haptic_intensity` names the scaling, `haptic_limit` only the +3 % / 8 s bounds (OWNERSHIP C5).
- **2026-10-21: Course grades.** `set_course_grade` is accepted only in `grade_source: game` phases (else `grade_source_not_game`) and the applied value moves at most every 0.5 s to the newest value (2 Hz). `course` phases follow `course_profile` by the distance from `set_course_distance` minus the distance at the phase start, linear between points, holding the first/last grade outside them, through the same 2 Hz coalescer. Every `set_course_grade` call is reported as a `course_grade` record.
- **2026-10-21: Virtual gears are fixed grade offsets tuned at a reference speed.** Gear g adds the grade that multiplies resistance at 30 km/h (83 kg, crr 0.004, cw 0.51) by 1.07^(g - 12) relative to the base grade (flat-road force for descents); gear 12 is neutral; gear 1 is about -2.5 % and gear 24 about +6.0 % on the flat. At 30 km/h every step is exactly 7 % at any base grade >= 0; at constant flywheel speeds elsewhere the step drifts: 8-17 % at 25 km/h, 4-6 % at 35 km/h, 2-4.5 % at 45 km/h (lower gears at low speed reach zero resistance like any descent). *Alternative:* offsets that track the rider's measured speed (7 % at every speed, but the grade then moves with the rider and costs extra writes). *Reason:* BRIEF 4.5 asks for a grade offset and allows a documented approximation; fixed offsets are deterministic and predictable. Shifts count only while the rider rides SIM; the gear survives phase changes.
- **2026-10-21: status() reports what the trainer is doing.** `mode` is the controller's written mode (so a 30 s SIM block shows about 30 s of SIM on a 1 Hz trace), `applied_target_w` the slewed target (0 outside ERG), `applied_grade_pct` the stacked grade while in SIM; `desired_mode` (`ERG`, `SIM`, `SAFE`, `OFF`), `governed_target_w`, `written_target_w` and `written_grade_pct` are added. `clamped_by` names `switch_ramp` while a switch runs or the ERG target climbs from a switch entry.
- **2026-10-21: Bad input.** `start_phase` outside the plan, `set_plan(null)`, a non-positive FTP and an unknown profile are `push_error`s and keep the previous state; out-of-range numeric configuration is clamped with `push_warning`; refused directives are `push_warning`s. `set_plan` keeps the current phase index when the new plan has it (a replan between phases).
- **2026-10-21: CadenceEstimator.** Present cadence passes through and teaches the km/h-per-rpm ratio (exponential average, alpha 0.1, only at >= 40 rpm and >= 5 km/h, and not from a repeated value while the speed moved > 5 %); an absent cadence, or one unchanged for more than `stale_s` while the speed moved > 15 %, is replaced by speed / ratio with `CADENCE_ESTIMATED`; a 10 s calibration sets the ratio from the mean speed at the target cadence. Added `cadence_age_s(now)` (for `Telemetry.cadence_age_s`) and `reset()`.
- **2026-10-21: The no-bypass scan lexes GDScript.** `tests/arch/test_no_bypass.gd` strips comments and string contents with a small GDScript lexer (normal, triple-quoted, raw, `&` and `^` strings), then flags any code reference to a guarded name that is not a `func` definition, and any string literal that is exactly a guarded name (dynamic `call`, `callv`, `Callable`, `call_deferred`, `has_method`). The allowlist is per file and per name. Fixtures prove it flags a bypassing script in a temp folder and passes comments, definitions and messages. Names built at run time can't be seen statically; review covers them.
- **2026-10-21 (hardening review): The scan also guards `request_stop`.** Besides the five names of BRIEF 4.6.11, `TrainerDevice.request_stop` (Stop, 0x08 0x01) may be called only by `trainer_controller.gd`: the TrainerDevice contract lists it with the setters, and the exit path (4.6.9) reaches it only through `SafetyGovernor.shutdown()`. `FtmsTrainer` and `MockTrainer` implement it (definitions are allowed) and never call it. *Alternative:* the five BRIEF names only. *Reason:* a Stop from anywhere else would bypass the governor's SIM-flat-then-Stop sequence; no current module calls it.
- **2026-10-21 (W2): A reconnect of the same device resyncs through the ramped path.** Decision: `SafetyGovernor.on_trainer_reconnected()` (additive) drops the stale 3 s power and calls `TrainerController.resync(crr, cw)`, which sets the written state to SIM flat (what `FtmsClient.begin()` leaves), forces the next SIM command to be written once even if it equals that guess, and counts the flow's own write for the 0.5 s slot. The current mode then comes back exactly like a first command: ERG through the SIM -> ERG entry max(floor, min(3 s power, governed target)) and 30 W/s slew, SIM by writing the stacked state. Plan, phase, warm-up, limits, rescue, coasting, gears and channels are kept; a reconnect is no directive switch for the 30 s spacing. Panic re-sends SIM flat at once; after `shutdown()` nothing is sent (only `setup()` revives). A new device object still goes through `setup(device)`. *Alternatives:* `setup(device)` again with the same object (resets to OFF and loses the slot accounting); re-sending the last written command as is (could jump straight to a high ERG target from SIM flat, against 4.5 and 4.6.2). *Reason:* BRIEF 4.4 "restore the last safe mode" with the 4.5 switch rules and 4.6.2 slew; the trainer really is at SIM flat after the flow.
- **2026-10-21 (W2): The no-bypass scan admits GdbleTransport's single hand-off by count.** Decision: `ALLOW_SITES` admits at most n call sites of a name per file (gdble_transport.gd: one `write_characteristic`, the `&"write_characteristic"` in `_device_write`); `bridge_transport.gd` and the transports no longer have a whole-file allowance (they only define `write_characteristic`, and definitions were never call sites). A second hand-off is flagged. *Alternative:* the whole-file allowance ble's W1 branch used. *Reason:* ble asked for exactly the one hand-off; a count keeps the scan as strict as possible for real call sites.
- **2026-10-21 (W2r2): With no phase the governor rides SIM grade 0, wind 0.** Decision: with no plan, a plan before its first `start_phase()`, or after the new `clear_plan()`, `_command_controller` sends `command_sim(0, 0, crr, cw)` instead of `command_off()`; `desired_mode` stays `OFF`, so it is no ERG/SIM switch for the 30 s spacing (as the connection flow's own SIM flat never was). From ERG the controller ramps there (4.5 step-down first). `clear_plan()` (additive) drops plan, phase and every channel and ends a rescue; warm-up, limits, gears and panic stay. *Alternatives:* keep `command_off()` (the trainer keeps whatever was written last: the cool-down's 50 % or an interrupted interval's target in the menus); count it as a switch (would refuse SIM blocks in the first 30 s of every session for no physical reason). *Reason:* platform's ADR says menus ride free at SIM flat, and after a session the trainer must not hold an ERG target nobody plans.
- **2026-10-21 (W2r2): Warm-up and the trainer's written state belong to the trainer connection.** Decision: the 4.6.8 warm-up state moves into `GovernorWarmup` (start, done, last pedal stroke on its own clock, advanced by the governor's ticks). `SafetyGovernor.adopt_connection(previous)` (additive) copies it, `TrainerController.adopt()` copies the written state and the time since the last write, and the rider's 3 s power history and latest speed carry over, when both governors are bound to the same device object. LocalRider calls it from `setup()`. Plan, phase, channels, rescue, coasting, duration limits, gears and panic stay per governor (per session). A new device object starts afresh; a reconnect keeps everything (same governor). *Alternatives:* keep one governor across sessions and reset its session state (its platform time, switch history and injected test governors would all need special cases); move only the warm-up (a fresh controller after a session would jump from the cool-down's ERG straight to SIM flat without the 4.5 step-down and could write within 0.5 s of the old controller's last write). *Reason:* BRIEF 4.6.8 counts warm-up "from the first pedal stroke after the trainer connects", and 4.5 ramps every switch from what the trainer really holds.
- **2026-10-21 (W2r2): No cadence is estimated from the flywheel while the rider coasts.** Decision: `CadenceEstimator` never estimates when the sample's power is below 15 W (BRIEF 3.5 not_pedaling): a reported cadence is kept even when it stays unchanged while the speed falls (a crank at rest reads 0), and an absent one stays absent. A frozen 0 rpm reading at 15 W or more is still stale. *Alternatives:* keep the W1 rule (a 0 rpm reading unchanged for 3 s while the flywheel spins down counts as a frozen estimate and becomes speed / ratio, so a coasting rider reads as pedaling for as long as the flywheel spins). *Reason:* found by the W2r2 warm-up tests: in SIM the mock's coasting speed made a stopped rider "pedal" for about 70 s, which would hide the coasting floor, pause and AFK (4.6.4), stop_5s and the warm-up's 20-minute reset (4.6.8) on a real trainer's spinning-down flywheel too.
- **2026-10-21 (W4, SAF-2): Duration limits belong to the trainer connection too.** Decision: `SafetyGovernor.adopt_connection()` also copies the time above 105% and above 120% FTP, both latches and the run of ERG at <= 90% FTP toward the 120 s reset, so they survive `LocalRider.setup()` on the same device object (every session and every menu reset builds a new governor). They reset only as BRIEF 4.6.1 says (120 consecutive seconds of ERG at <= 90% FTP) or with a new trainer connection (another device object). Supersedes the W2r2 line "duration limits ... stay per governor (per session)". *Alternatives:* keep them per session (W3: End ride while latched, then a session whose first 300 s are SIM, gave a fresh 60 s / 300 s budget with no reset run); one governor for the whole connection (its platform time, switch history and injected test governors would all need special cases). *Reason:* 4.6.1 names one release condition, and ending a session is not it.
- **2026-10-21 (W4, SAF-6): The menus' SIM flat counts as SIM for the 30 s spacing.** Decision: with no phase the governor commands SIM grade 0 (W2r2), so for switch tracking OFF is SIM: ERG -> OFF (`clear_plan()`) is a switch, and OFF -> ERG is one when the controller has the trainer at SIM (the menus, the connection flow's SIM flat after a resync, a cool-down that already stepped down). A governor whose controller has written nothing yet knows no previous mode, so its first ERG is no switch (in-process simulations and the governor rig start that way). `adopt_connection()` carries the last switch time, rebased onto the new governor's clock. The sdk's `PhaseTracker` still starts at NO_SWITCH; the rider's governor refuses such a block either way (requests for lead). Supersedes the W2r2 reason "would refuse SIM blocks ... for no physical reason". *Alternatives:* count OFF -> ERG always (a fresh rig's first ERG would refuse every early SIM block although nothing was written); keep OFF as no mode (W3: SIM -> ERG -> SIM within 1 s at a session start). *Reason:* BRIEF 4.5 counts from "the rider's previous switch" at the trainer, and since W2r2 the menus really hold SIM flat.
- **2026-10-21 (W4, SAF-7): A stale-sample watchdog.** Decision: while the device reports a link (status not disconnected, scanning or connecting), no trainer sample for more than `STALE_SAMPLE_S` (3 s, LocalRider's `STALE_S`) counts as one not_pedaling sample (0 W, no cadence) at the moment the stream went stale, fed through the same per-sample path as a real one: the coasting floor follows 3 s later, pause/AFK 10 s after that, and the rescue power trigger sees 0 W (the coasting floor wins over rescue, 4.6.12). It fires once per stale stretch; the next real sample ends it. The watchdog counts from `setup(device)`, a reconnect (`on_trainer_reconnected`) or the latest sample, and `adopt_connection()` carries it. Status gains `samples_stale` (and `reset_run_s` for SAF-2), both additive. *Alternatives:* inject the synthetic sample in LocalRider (the governor is the safety authority and also runs without LocalRider in tests and tools); count from the last sample itself (coasting 3 s after a rider was last seen pedaling, before the stream is even stale); also while the link is down (a link drop is the reconnect flow's job, and the re-entry already starts at the floor). *Reason:* BRIEF 4.6.4 times coasting from samples, but a KICKR that stops notifying left the ERG target at the interval's value while the telemetry already showed 0 W. Hardware check: whether the KICKR CORE keeps sending Indoor Bike Data at about 1 Hz with zeros when the flywheel stops, and how long notifications can stall on Windows/GDBLE while the link stays up (requests for lead: a HARDWARE_TEST_PLAN item).
- **2026-10-21 (W4, SAF-1): `configure()` rejects an FTP outside 30-2000 W.** Decision: `GovernorClamps.FTP_MIN_W` / `FTP_MAX_W` (the range Settings clamps a profile into); `configure({ftp_w})` outside it push_errors and keeps the previous value (the default 200 W for a new governor). *Alternatives:* clamp into the range with a warning (an absurd FTP from a hostile session_start would still set a 2000 W basis); keep "> 0" (W3: 5000 W from a host gave a 1500 W floor). *Reason:* BRIEF 4.6.7, the client validates locally; the rider's own FTP comes from the profile (LocalRider, docs/decisions/platform.md).
- **2026-10-21 (W4, SAF-4): The 4.6.11 scan also holds games to ctx.directives.** Decision: under `src/games/`, `tests/arch/test_no_bypass.gd` also fails on references to the trainer stack's classes and autoload (TrainerService, LocalRider, SafetyGovernor, TrainerController, the devices, FtmsClient, the connection manager and transports, DirectiveRouter, HudRouter), on `.governor`, `.configure_governor`, `.emergency_safe`, `.resume`, `.local_rider`, `.trainer_service`, `._riders`, `directives.riders` and `hud.riders`, on bare calls of `configure_governor(`, `emergency_safe(` and `resume(` (definitions excepted), and on those names as exact string literals; `.tscn` and `.tres` files are scanned as text everywhere for the guarded setters and, under `src/games/`, for those names and for script paths into the trainer stack. A bare `.riders` is not flagged because Workout's own `WorkoutState.riders` is a game field; the routers' maps go private in the sdk (session fixer). *Reason:* W3's fixture game reconfigured the governor to ramp_test, set an unvalidated 200% plan and called resume() with 0 violations.
- **2026-10-21 (W4r2, SAF-4 recheck): The scan also closes the GameHost route.** A GameModule is its GameHost's child, so `get_parent()` reached the host's rider map and `LocalRider.setup({governor_profile: "ramp_test", skip_warmup: true})`, `set_plan()` and `start_phase()` without a guarded name. Decision: under `src/games/` the scan also fails on `GameHost`, on any member access whose name holds `local_rider` (`.local_riders`, `._local_riders`, an accessor), on `governor_profile` anywhere in code or as a string, on a string naming a stack script's file (a preload or load by path), on the exact strings `set_plan`, `start_phase` and `resume_phase`, and on calls of `.setup(`, `.set_plan(`, `.start_phase(` and `.resume_phase(` on a receiver that is not rooted at `ctx`, `self` or `super`, unless the receiver is a plain variable that the file declares, in every declaration, with a type that can't hold a LocalRider, SafetyGovernor or GameHost (anything but untyped, Variant, Object, Node or a stack class). *Alternatives:* flag every `.setup(` on a non-ctx receiver (Siege's `MultiMeshScatter.setup(mesh, capacity)`, a 3D-kit API in GAME_SDK 18, and every game view's own `setup` would fail the gate, which games can't change); flag a bare "setup" string too (a common state name; a dynamic call needs a rider reference, which the other rules guard). *Reason:* a typed GDScript variable can't hold an object of an unrelated class at run time, so a typed receiver is provably not the rider, and the static-typing rule (BRIEF 6) already asks games to type their variables.
