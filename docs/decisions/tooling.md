# Decisions: tooling (Godot wrappers, Godot lock, env scripts, test runner, script check)

Short ADRs for `tools/godot.sh`, `tools/godot.ps1`, `tools/lib/godot_lock.mjs`, `tools/lib/wrapper_common.ps1`, `tools/env.sh`, `tools/env.ps1`, `tools/run_tests`, `tools/run_tests.ps1`, `tools/lib/run_tests.mjs`, `tools/lib/gut_gate.mjs`, `tools/check_scripts.gd` and `tools/tests/` (BRIEF 1, 2, 7).

- **2026-10-21: Lock state is files that are created or deleted, never rewritten.** Each request gets `t-<seq>.json` (pid, lease, label; created exclusively), and a grant creates `h-<seq>`. No `h-` file means "waiting". Ticket numbers come from a `seq` counter that is only touched under an exclusive-create `seq.mutex`, and a mutex left by a dead process (or older than 10 s) is broken. *Alternatives:* a state field rewritten inside the ticket; `flock`; a lock daemon. *Reason:* every state change is one exclusive create or one unlink, which is atomic on NTFS and POSIX, so readers never see a half-written state, and there's no Windows rename-over-open-file failure. `flock` doesn't exist in Git Bash, and a daemon would be one more process to babysit.
- **2026-10-21: Strict FIFO grants with whole leases.** A ticket is granted only when no lower-numbered ticket is waiting, and either `held + lease <= cap`, or `lease > cap` and nothing is held. *Alternatives:* best fit, or letting small requests overtake. *Reason:* BRIEF 2 requires it, and it's the only rule under which a waiting e2e lease (3 slots) can't be starved by a stream of 1-slot runs. Tested with a 4-slot lease at cap 4, a 3-slot lease at cap 4 behind 2 held slots, and a 3-slot lease above cap 2.
- **2026-10-21: Dead tickets are found by pid first, then by heartbeat.** A ticket whose pid is gone is reaped at once. Each ticket's mtime is touched every 5 s from a worker thread, and a ticket with a live pid but no heartbeat for 60 s is reaped once the waiter has seen it stale over 10 s of its own uninterrupted polling. *Alternatives:* pid only; heartbeat only. *Reason:* Windows reuses pids, so pid alone could block the queue forever behind a crashed run. The worker thread keeps beating while a library user blocks its main thread (for example in `spawnSync`). The polling-gap rule stops a machine waking from sleep from reaping live holders.
- **2026-10-21: The cap is re-read on every poll.** `machineCap()` returns `WATTLANDS_GODOT_LOCK_CAP` if set, else 4 with at least 8 CPUs and 16 GiB `os.freemem()`, else 2. *Alternative:* fix the cap once per process. *Reason:* free memory drops as Godot processes start, so later grants see the real headroom. Tests and harnesses read the same override.
- **2026-10-21: `WATTLANDS_GODOT_LEASE_TOKEN` (additive).** `acquire()` returns `handle.token`. Passing it to `tools/godot.sh` or `.ps1` runs Godot inside that held lease without queueing again, and an invalid or released token falls back to normal queueing with a warning. *Alternatives:* the e2e harness starts the Godot binary directly, or nests a second acquire. *Reason:* BRIEF 2 has the e2e harness hold one lease for its host and two clients. Starting Godot directly would duplicate the env, user-dir, `-d` and timeout rules, and a nested acquire deadlocks when the lease is above the cap. The harness must start at most `lease` Godot processes under one token.
- **2026-10-21: The lock CLI's exit codes.** It returns Godot's own code, 124 on the run timeout ("godot run timeout"), 75 on the lock wait timeout ("godot lock wait timeout", and nothing was started), 127 when the program can't be started, 2 on usage errors, and 128+n on a signal. The lock is released on every path, including SIGINT, SIGTERM, SIGHUP and SIGBREAK, and a waiting ticket is withdrawn.
- **2026-10-21: Window hiding.** The runner sets `windowsHide` only for `--headless` runs and for Godot's `_console.exe`, which starts the real windowed exe as its own child, so that window stays visible. *Reason:* on Windows, `windowsHide` also hides the child's first GUI window, and windowed runs (screenshots, Siege's windowed perf run) must stay visible. Checked by hand: a windowed run through the wrapper showed a visible window.
- **2026-10-21: Timeouts kill the whole tree.** `taskkill /T /F` on Windows. On POSIX the child gets its own process group and the group is SIGKILLed. A test checks that the real Godot process, the grandchild of the runner on Windows, is gone after `--timeout`.
- **2026-10-21: "This checkout" means the wrapper's own checkout.** Binary resolution reads `tools/godot_bin.local` next to the wrapper, then in the main checkout (`dirname $(git rev-parse --path-format=absolute --git-common-dir)`), then looks for `godot` or `godot4` on PATH. A `godot_bin.local` that names a missing file is skipped with a warning. *Reason:* this works from any cwd and in every worktree (tested with a real `git worktree`).
- **2026-10-21: The user dir.** It's `<--path or git toplevel or cwd>/.userdata`: `APPDATA` on Windows (converted with `cygpath -m` in Git Bash), `XDG_DATA_HOME` on Linux. The wrapper creates the folder. Runs with `--export-release`, `--export-debug`, `--export-pack` or `--export-patch` keep the real user dir.
- **2026-10-21: Git Bash keeps MSYS's default argument conversion.** POSIX paths such as `/c/x` or `/tmp/x` become Windows paths for Godot. URLs, `res://` paths, JSON and arguments with spaces pass unchanged (tested). *Alternative:* `MSYS2_ARG_CONV_EXCL='*'`. *Reason:* Godot is a native program and needs Windows paths.
- **2026-10-21: `godot.ps1` reconstructs arguments typed at a PowerShell prompt.** Started with `-File`, PowerShell passes arguments untouched. Called directly, it drops a bare `--`, splits `-gdir=res://tests` at the colon and turns `a,b` into an array. `tools/lib/wrapper_common.ps1` rebuilds the typed words from the parser's AST of `$MyInvocation.Line` (adjacent tokens are joined, and the result is checked against `$args`). When that isn't possible it falls back to `$args`, rejoins `-x:` pairs and warns about a lost `--`. *Alternative:* document "always quote '--'". *Reason:* agents and humans type the GUT command from CLAUDE.md as-is, and a split `-gdir` would silently run nothing.
- **2026-10-21: PowerShell starts native programs through `System.Diagnostics.Process`.** It applies exact Windows argument quoting, uses the caller's current location as the working directory, and makes temporary environment changes that are restored right after start. *Reasons:* PowerShell 5.1 drops embedded double quotes when it calls a native program. A direct call would otherwise leak `APPDATA` and the lock variables into the user's session. With PATHEXT missing (an emptied environment), `&` opens an exe like a document, with no output and no exit code. Program lookup also scans PATH itself when `Get-Command` finds nothing, and the Windows check uses `[Environment]::OSVersion`, not `$env:OS`.
- **2026-10-21: One Node core for both runners.** `tools/run_tests` and `tools/run_tests.ps1` are thin shims over `tools/lib/run_tests.mjs`, which holds a `STEPS` list with one function per step: import, gut, scaffold, static, sim, fit, node, e2e. Godot steps go through `tools/godot.sh` (bash shim) or `tools/godot.ps1` (PowerShell shim). *Alternative:* separate bash and PowerShell implementations. *Reason:* identical behaviour, one place for the lead's W2 steps (scaffold, sim, fit and e2e are marked SKIP "not wired yet" until then), and gate logic that can be unit-tested (`tools/lib/gut_gate.mjs`).
- **2026-10-21: The GUT gate.** A run passes on exit 0, "Run Summary" in the log, a JUnit count above 0 and at least the required count, and none of BRIEF 7's five strings in the log. The required count is `--min-count`, else `build/green_count.txt`. `build/junit.xml` is deleted before each run, so a stale file can't pass. The green count is written after every green full run, including one that `--min-count` lowered, and the runner prints when that happens. Narrow runs (`--gdir`, `--gut-arg`) neither compare nor update it.
- **2026-10-21: `import` is never a gate.** A non-zero exit shows as WARN in the summary. The summary rows are PASS, FAIL, SKIP and WARN, and only FAIL makes the exit code non-zero.
- **2026-10-21: gdlint and gdformat --check are reported, not fatal, unless `--strict-lint` is passed.** Detection tries `gdlint` on PATH, then `uvx --from gdtoolkit==4.*` (gdtoolkit 4.5.0 works here), with a 90 s probe. Without it the runner prints "gdtoolkit unavailable, skipped". `--no-lint` skips both. *Reason:* BRIEF 7.2 makes them conditional on Python, gdtoolkit can lag GDScript 4.7 syntax, and style findings shouldn't block P0. The findings are in the summary and in `build/gdlint.log` and `build/gdformat.log`. *Superseded 2026-10-21* by docs/decisions/lead.md: lint is fatal whenever gdtoolkit 4.5.0 is available, `--strict-lint` is a no-op, and `./gdlintrc` configures gdlint.
- **2026-10-21: `check_scripts.gd` also fails on logged load errors.** In Godot 4.7, a script with a parse error loads as non-null with `can_instantiate()` false. An `@abstract` script with a parse error would pass both of the brief's checks. So the checker registers an `OS.add_logger()` Logger (Godot 4.5+) and fails any script whose load logs an error (warnings excluded). It skips dot-folders and folders with a `.gdignore`, since Godot never imports them.
- **2026-10-21: The node step.** It runs `node --test` with each suite directory as cwd (node's default file patterns) and skips a directory without test files. `WATTLANDS_RUN_TESTS_NESTED` stops a Node suite that starts `tools/run_tests` from recursing. Each suite has a 30 min timeout with a tree kill.
- **2026-10-21: `tools/run_tests` removes `FAL_KEY` and `WATTLANDS_ALLOW_ART` for its own process tree** (docs/OWNERSHIP.md TL5), so no gate can make a paid fal call even in a session where Simon has set them. `tools/env.*` and the Godot wrappers still never name either variable, and a test scans them for that.
- **2026-10-21: Tooling tests never touch the main checkout's Godot cache.** Real-Godot tests run in scratch projects under `build/` (which has a `.gdignore`) and queue on the real machine-wide lock. Lock-logic tests use temp lock directories. The "empty environment" for the wrapper tests is PATH (bash, node, git, System32, WindowsPowerShell), SystemRoot and TEMP/TMP. TEMP is kept so `os.tmpdir()`, and with it the machine-wide lock directory, stays the same.
