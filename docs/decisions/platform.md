# Decisions: platform (addons/wattlands/core)

Short ADRs for `WlSettings`, `WlApp`, `WlTrainerService`, `LocalRider`, `FtpTest` and `AutoloadLookup` (BRIEF 3.2, 3.5, 4.1, 4.6.9, 6).

- **2026-10-21: A missing settings file is a normal first run; a corrupt one warns.** Decision: a missing `profile.json` or `settings.json` gives the defaults silently; unparsable JSON or a non-object gives the defaults with `push_warning`; single values of the wrong type are dropped and numbers out of range clamped (`WlSettings.PROFILE_RANGES`), each with `push_warning`. `set_value` refuses a wrong type for a documented key with `push_error`; other modules may store their own JSON keys. Files are written to `<name>.tmp` and renamed over the old file. Alternatives: warn on missing files too; refuse to start on a corrupt file. Reason: every first launch and every test temp dir starts without files, and a hand-edited or half-written file must never block riding (an FTP of 0 or a weight of 5000 would reach the governor).
- **2026-10-21: `--strava-base=<url>` is a server root.** Decision: the API base becomes `<url>/api/v3` and the OAuth base `<url>/oauth` (a trailing `/api/v3` or `/oauth` is stripped first), for this run only, never saved; `--relay` likewise. Alternatives: use the URL as-is for both. Reason: the real Strava layout is `https://www.strava.com` + `/api/v3` and `/oauth`, and `tests/core/test_locks.gd` already uses `http://localhost:8899/api/v3/uploads`, so `server/mock_strava` can mirror the real paths. Rides reads `Settings.strava_api_base()` and `strava_oauth_base()`.
- **2026-10-21: Recent rooms and the last trainer live in `settings.json`.** Decision: `recent_rooms` (`{code, at, role}`, normalized code, `HOST`/`CLIENT`, newest first, one per code, at most 8, UTC `at`) and `last_device` are settings keys as the W0 stub documents; `TrainerService` copies `FtmsConnectionManager.last_device()` into `last_device` on every `trainer_ready`. `Paths.recent_rooms_path()` stays for compatibility; ble keeps its own `last_device.json`. Alternatives: separate files. Reason: one file, one loader, one corruption rule; the app shell reads both through `Settings`.
- **2026-10-21: One time base per rider.** Decision: `LocalRider` keeps its own platform time (integer microseconds, from 0 at each `setup()`), queues device samples when they arrive and processes them in the next `tick()` as copies stamped with that time. The governor, gestures, recorder and `Telemetry.t` all use it. Alternatives: pass the device's `sample.t` through. Reason: a MockTrainer or FtmsTrainer created before the rider (menus, reconnects) has another clock origin, and the governor's rescue, coasting and 3 s power rules must compare sample times with its own tick time.
- **2026-10-21: Raw trainer values in telemetry; the speed model drives the course.** Decision: `Telemetry.power_w`, `cadence_rpm` and `speed_kmh` are the trainer's, `distance_m` integrates the trainer's reported speed (the `Telemetry` contract and the recorder use that), and the speed model (P_eff on the applied SIM grade, 0 outside SIM) feeds only `SafetyGovernor.set_course_distance()`. A sample older than 3 s counts as gone (power, cadence and speed 0). W' balance steps every tick on the latest raw power; the recorder gets the latest values every tick and keeps 1 Hz itself. Alternatives: speed model speed in telemetry; W' and the recorder per sample. Reason: BRIEF 3.4 asks for W' every sim tick, per-tick feeding can't skip a second when notifications jitter to 1.1 s, and games integrate their own speed model (BRIEF 3.11).
- **2026-10-21: Exactly one ack per governor record.** Decision: every `directive_applied` record the governor emits is re-emitted by the rider and queued for `take_acks()` as `{id, kind, applied, clamped_by, refused, reason}`; `apply_directive()` queues the returned record itself only if the governor didn't emit during the call. Alternatives: ack only what `apply_directive` returns. Reason: course grades and other governor records also need acks, and the stub doc lets the governor both return and emit.
- **2026-10-21: A process-wide live-rider list for the exit paths.** Decision: `LocalRider.live_riders()` (weak references, filled by `setup()`, emptied by `shutdown()` and freeing) is what `WlTrainerService.shutdown_all()` walks on quit, window close, crash and tree exit. Alternatives: a register/unregister API on TrainerService that GameHost and GameSimRunner must call. Reason: BRIEF 4.6.9 must cover session and bot riders too, and a frozen GameHost stub can't be asked to call a new API in W1.
- **2026-10-21: The App boots only in the real app.** Decision: `WlApp._ready` defers `boot()` only when the SceneTree has no script; under GUT, `check_scripts.gd` or a tool's `-s` driver the App autoload stays in `boot` and never starts the trainer. A scripted peer (`--host`/`--join`) goes to `lobby` with `launch_options()`; the app shell drives it from there. Alternatives: boot always and stub Bluetooth in tests; an explicit `--no-boot` flag. Reason: no Bluetooth activity in tests (BRIEF 1) without asking every test runner to pass a flag.
- **2026-10-21: quit() order.** Decision: `goto("quitting")`, emit `quitting(code)` (the app shell saves rides and writes `--report` with the stack still up), save any ride still recording, `TrainerService.shutdown_all()` (SIM flat, then Stop), write a minimal scripted-peer report if `--report` was given and nobody wrote one, then quit, after 0.5 s of real time when a real trainer is connected so the safe commands can leave. A window close request runs the same path (auto-accept-quit is off in the real app); `NOTIFICATION_CRASH` and leaving the tree after boot shut the riders down at once. `--run-seconds` counts the App's own SimClock at `--sim-speed` and quits with `run_seconds_exit_code` (default 0). Alternatives: write the full report in the platform. Reason: the report's contents are session data the app shell owns; the harness still always finds a JSON file.
- **2026-10-21: The menu-time rider.** Decision: `TrainerService` builds its `LocalRider` (peer 1, profile slot in the saved scaling mode, solo, not recorded) as soon as a trainer exists, attaches it to the InputRouter, and ticks it on its own SimClock (`--sim-speed`) until `set_external_tick(true)`. Profile and scaling changes outside a session set the rider up again (a mock whose FTP, CP, W', cadence or weight changed is rebuilt); `hold_rider(true)` defers that, and releasing sets the rider up afresh. `EventBus.panic_requested` calls the rider's `panic()`. Switching trainers shuts the old rider down first. Alternatives: create the rider only for sessions. Reason: pedal gestures drive every menu (BRIEF 3.5), and the FTP test's cool-down must not be rebuilt by its own profile save.
- **2026-10-21: FTP test details.** Decision: `FtpTest` is pure logic (`start`, `step(dt, telemetry)`, `back`) plus `run_on(rider)`. The steps go up to min(1000 W, trainer max), at least one, at most 120. The power rule needs an ERG target above 0; the cadence rule ignores a cadence older than 3 s, so a trainer without cadence can finish. Rescue and coasting end at once and the cool-down phase starts in the same tick. The 10 s save countdown runs at the start of the cool-down, which continues; `back` cancels it. A test ended in the ramp-in or with `back` gives no result. Saving sets FTP, CP = FTP and `ftp_verified`. Alternatives: count down after the cool-down; save results from the ramp-in. Reason: the rider sees the result while still pedaling easily, and an estimate from a 50-65% ramp is meaningless.
- **2026-10-21: `AutoloadLookup` instead of autoload globals.** Decision: platform classes find `EventBus`, `Settings`, `TrainerService`, `Rides`, `InputRouter` and `App` through `/root` at run time and every class takes an injected instance first. Alternatives: name the autoloads as globals. Reason: the same classes run in GUT, in tools and in in-process multi-peer simulations, where each peer has its own bus (OWNERSHIP 3.1 C28).
- **2026-10-21: Handing ticking back makes the session rider the menu rider again.** Decision: `TrainerService.set_external_tick(false)` after `true` sets its rider up afresh (peer 1, the profile's slot, solo, no plan, no recorder, a fresh governor) and applies any profile or scaling change made during the session; while that rider's ride still records, the reset waits until `finish_ride()` (checked every menu step, `is_menu_reset_pending()`). Profile changes during a session wait for the hand-back instead of being dropped. `App.quit()` shuts the riders down before handing ticking back, so quitting never builds a menu rider and the shut-down governor keeps being ticked for its safe commands. Alternatives: leave the session's governor and plan in place in menus; reset at once and drop an unsaved ride. Reason: menus must ride free in SIM flat with solo gestures (coast never fires in ERG), and the results screen must still be able to save the ride.
- **2026-10-21: A ride is never lost to a rebuild.** Decision: `LocalRider.setup()` on a rider whose ride still records stops and saves that ride first (`push_warning`), and `TrainerService` does the same before switching trainers. Alternatives: drop it silently; refuse the setup. Reason: a saved ride is the one artefact a rider keeps (BRIEF 3.8), and the exit path already saves open rides.
- **2026-10-21: A new trainer object mid-session is rebound, not rebuilt.** Decision: `LocalRider.rebind_device(d)` keeps plan, phase, time, queues and recorder and calls `governor.setup(d)` again; `TrainerService` uses it when `trainer_ready` hands over a different device object while a GameHost ticks the rider (menus still rebuild the rider). Alternatives: free the rider and build a new one. Reason: the GameHost holds the rider; freeing it mid-session would crash the session. trainer-control's `setup()` must accept a second call that rebinds its controller.
- **2026-10-21: Setup clears a reused MockTrainer.** Decision: `LocalRider.setup()` clears the mock's cadence and power bands and sets its phase to -1. Alternatives: rely on the cool-down to clear bands. Reason: the app's `--mock-trainer` mock lives across sessions, and a session left before its cool-down would otherwise steer the next session's mock rider.
- **2026-10-21: FIT lap names are text.** Decision: lap names from phase labels and `lap_marker` labels go through `TranslationServer.translate` (strings keys become text, plain text passes through); unlabelled lap phases are `CORE_LAP_PHASE` ("Phase {n}") and the cool-down without a label `CORE_LAP_COOLDOWN`. Alternatives: the raw label. Reason: PL11 allows a strings key as a label (Tank), and Strava shows the lap name.
- **2026-10-21: settings.json holds JSON values only.** Decision: `set_value` refuses anything that doesn't survive JSON as itself (vectors, colors, non-string keys, NaN) with `push_error`; `set_last_device` first round-trips its dictionary through JSON (packed arrays become arrays). Alternatives: store whatever `JSON.stringify` makes of it. Reason: a value that comes back as a different type after a restart is a latent bug in another module.
- **2026-10-21: A dropped FtpTest lets go.** Decision: an `FtpTest` freed while driving a rider (the screen dropped it without `stop()`) puts the governor back on its normal profile and releases the TrainerService hold from `NOTIFICATION_PREDELETE`. Alternatives: rely on `stop()`. Reason: a forgotten hold would freeze every later profile change for the menu rider.
- **2026-10-21 (W2): Same-object reconnects resync the governor.** Decision: `FtmsConnectionManager` keeps one `FtmsTrainer` per address, so a reconnect hands `TrainerService` the same object (`trainer_ready`, then `reconnected`). `TrainerService` now listens to `reconnected` and calls the additive `LocalRider.trainer_reconnected()`, which calls `SafetyGovernor.on_trainer_reconnected()` (restore the last safe mode through the ramped path, BRIEF 4.4). A new object still goes through `rebind_device` (in a session) or a rebuilt rider (menus), and its `reconnected` then resyncs too. `rebind_device` with the same object stays a no-op. *Alternative:* make `rebind_device(same)` resync. *Reason:* the reconnect is a distinct event from a rebind, and the tested W1 contract of `rebind_device` stays.
- **2026-10-21 (W2): LocalRider fires timed gestures every tick and records absent values as absent.** Decision: `tick()` calls `GestureRecognizer.advance(t)` after the samples, so coast and stop_5s fire on the tick they are due rather than with the next ~1 Hz sample; the recorder gets -1 (absent) for a cadence or speed the trainer doesn't report or a stale sample's (power 0 W), and RideRecorder keeps its 1 Hz thinning of the per-tick calls. *Reason:* sim's integration note; no invented 0 rpm cadence in the FIT.
- **2026-10-21 (W2): Acks carry `refused` as a bool and `dropped`.** Decision: `take_acks()` entries are `{id, kind, applied, clamped_by, refused (bool), reason, dropped: [{channel, reason}]}`. *Reason:* trainer-control's records carry a bool and the dropped haptic channel; the lead fixes the Telemetry.acks comment.
- **2026-10-21 (W2): `Paths.get_override()` and `RiderProfile.show_wkg`.** Decision: additive. `get_override()` returns the normalised override ("" when none) so run_game_sim can restore it; `show_wkg` (default false, in to_dict/from_dict) is the rider's opt-in to see W/kg on the HUD and results, independent of `share_weight` (W/kg is computed locally). *Reason:* sdk-tools and ui-hud requests.
- **2026-10-21 (W2): setup() restarts a MockTrainer's profile.** Decision: besides clearing the bands and phase, `LocalRider.setup()` calls `MockTrainer.restart_profile()`, so `cadence_drop:at_s`, surges, ramps and intervals count from the session's setup (the rider's platform time 0) even when the `--mock-trainer` mock rode through the menus first. *Alternative:* leave it to each caller (trainer-core's W1 note); nobody called it. *Reason:* a profile scripted for a session must not depend on how long the menus took.
- **2026-10-21 (W2): `TrainerService.set_menu_ticking(on)`.** Decision: an additive alias of `set_external_tick(not on)`, which the app shell already calls duck-typed at the start (false) and end (true) of a session and of the FTP test. *Reason:* without it the service kept ticking the rider from its own clock while the GameHost ticked it too (two ticks per frame in the windowed app).
- **2026-10-21 (W2): A scripted peer's hard stop and report belong to the app shell.** Decision: following docs/ARCHITECTURE.md "Scripted peers" (lead, after W1), `WlApp` ignores `--run-seconds` and writes no fallback `--report` when `is_scripted()`; the shell stops with exit 2 and writes the full report after `App.quit()`. Non-scripted runs keep the `--run-seconds` quit and the fallback report. This supersedes the W1 "quit() order" ADR for scripted peers. *Reason:* WlApp's own clock started at boot, so it reached `--run-seconds` before the shell's and quit with 0 and a minimal report, hiding the shell's exit 2 and report from the e2e harness.
- **2026-10-21 (W2r2): LocalRider.tick() ends when a handler sets the rider up again.** Decision: `setup()` bumps a generation counter; `tick()` reads it at the start and returns as soon as it changed (after `device.tick`, each sample, the timed gestures and `governor.tick`), and `_queue_gestures` stops emitting the rest of a batch. *Alternatives:* defer `setup()` calls made during a tick to its end (callers expect the new setup at once, the session start reads the rider right after). *Reason:* a menu pick made from a gesture handler (a pedal-scan pick that starts a session) set the rider up mid-tick, and the rest of the tick fed the old platform time into the new governor, gestures and ride (a FIT record at the menu's time).
- **2026-10-21 (W2r2): The menu reset re-attaches the rider, drops the plan at once and keeps the connection.** Decision: `_rebuild_menu_rider()` attaches the rider to the InputRouter again (GameHost.end_session detaches it); when the reset must wait for a ride still recording, `LocalRider.clear_plan()` (additive) drops the session plan at once so the governor rides SIM flat meanwhile; `LocalRider.setup()` on the same device object calls `SafetyGovernor.adopt_connection()` on the governor it replaces, so the warm-up continues from the menus into a session and back, and the step from the cool-down's ERG to the menus' SIM flat is ramped from the trainer's real state. *Alternatives:* leave the re-attach to the app shell's AppSessionInput (only the session screen does it); keep the plan until the ride is saved (the trainer would hold the interval's ERG target in the menus). *Reason:* BRIEF 4.6.8 counts the warm-up from the first pedal stroke after the trainer connects, and the menus ride free at SIM flat.
- **2026-10-21 (W2r2): `--mock-keyboard` turns on MockTrainer's keyboard control.** Decision: `WlTrainerService.use_mock()` passes `keyboard: CmdLine.get_bool("mock-keyboard", false)` to every mock it builds (the `--mock-trainer` one, a rebuilt one after a profile change, one picked in Settings). Without the flag the mock never reads a key. *Alternative:* turn it on with every `--mock-trainer` (W/S/A/D would move the rider whenever a keyboard user navigates the menus). *Reason:* BRIEF 4.2's keys are also BRIEF 3.5's movement keys, so the overlap must be asked for; the lead adds the flag to CLAUDE.md's list.
- **2026-10-21 (W2 round 2, app): An FTP result needs one completed step; `FtpTest.save_now()`.** Decision: `FtpTest` counts a result only when at least one one-minute step was completed (`steps_completed >= 1`) and the test wasn't ended with `back()`; before, reaching the steps was enough, so a stop a few seconds into step 1 saved 0.75 x a ramp-in minute. The additive `save_now()` saves during the countdown at once (the page's Save item). The cadence rule stays as it was: it counts only a fresh cadence (`Telemetry.cadence_age_s` <= 3 s), which includes the CadenceEstimator's speed-based estimate, so a trainer without cadence (and nothing to estimate from) never ends the test on it. `FtpTest` is now the one implementation; the app's `AppFtpTest` is gone. *Alternatives:* keep the app's copy; count the steps as reached. *Reason:* BRIEF 3.2 (one-minute steps, best 1-minute power) and the lead's round-2 item: a test stopped in the ramp-in or before one step was done has no FTP to save.
- **2026-10-21 (W4, SAF-1): The local human rider's safety values come from the rider's own profile.** Decision: `LocalRider.setup()` given both a profile and a slot for a human (not a bot) overwrites the slot's `ftp`, `ftp_verified`, `haptics_on` and `haptic_intensity` from the profile before configuring the governor, with push_warning when they differed. A CLIENT's slot comes from the host's session_start, so a modified or buggy host can no longer set the client's watt basis, lift the 0.85 unverified factor or turn opted-out haptics back on. A null profile keeps the slot as given (tests, in-process riders); bots keep the lobby's bot FTP. The app's session launcher is fixed separately (app fixer). *Alternatives:* copy the slot instead of changing it (the session's `ctx.players` would then show the host's numbers for the local rider while the governor used others); fix only the launcher (every other caller would stay exposed). *Reason:* BRIEF 3.3 "ERG targets always come from each rider's own FTP", 4.6.7 "each client validates and clamps them locally".
- **2026-10-21 (W4, SAF-3): `--sim-speed` only with a MockTrainer.** Decision: `WlTrainerService.effective_sim_speed()` (additive) is the flag with a MockTrainer (or before any device when `--mock-trainer` is given) and 1 with a real trainer (push_warning once). The menu clock follows it whenever the device changes; the app's session launcher uses the same helper for the GameHost's clock (app fixer). *Alternatives:* forbid the flag in the app (scripted mock runs use it); scale nothing on platform time (the mock rider and the sims need it). *Reason:* every governor time rule (30 W/s slew, 2 writes per second, rescue, coasting, warm-up) must hold in wall time on a real trainer.
- **2026-10-21 (W4, SAF-8): Disconnect, switch and "use mock" make the trainer safe before the link drops.** Decision: `WlTrainerService.disconnect_trainer()` and `connect_trainer(address)` (additive; Settings calls them, app fixer) and `use_mock()` shut the rider down first (its governor sends SIM flat, then Stop, through the controller) and release it, then run the link action (`FtmsConnectionManager.disconnect_trainer()`, `connect_to()`, or dropping and freeing the old manager) once the FTMS control point has sent both (queue empty and nothing in flight, or the client not in control), or after `SAFE_UNLINK_TIMEOUT_S` = 3 s (push_warning). Without a pending write (a mock, a fake manager, the hardware lock) it happens at once, so `use_mock()` still switches synchronously. After a disconnect `device()` is null until a trainer is ready again, which sets a new rider up. The connection manager also releases the old `FtmsTrainer` from the shared client on a switch (docs/decisions/ble.md). *Alternatives:* a fixed 0.5 s wait like `App.quit` (too short for a retried write, too long when nothing is pending); shut down inside the manager ("the manager never writes to the trainer itself"). *Reason:* BRIEF 4.6.9 "on exit, crash paths and disconnect: try SIM flat, then Stop"; W3 found that none of the three paths sent Stop, and a switch sent the old rider's SIM flat and Stop to the new trainer.
- **2026-10-21 (W4, NET-6): A host quitting the app leaves its room.** Decision: `WlApp.quit()` calls `NetSession.leave()` (after the quitting signal, so rides and reports go first) when this peer hosts a room (role HOST, not the offline lobby, state not offline or error), and then waits `QUIT_GRACE_S` of real time before the tree quits so the relay transport sends it. A client never leaves on quit: its saved reconnect token lets a restarted client rejoin. `WlApp.net_session` (injection) and `AutoloadLookup.net()` are additive. The client-side notice is the app fixer's. *Reason:* BRIEF 5.3 sends host_left "only on an explicit leave", and 5.5 says "If the host leaves, end the session gracefully"; a window close looked like a drop, so clients sat 120 s in the dropped-host hold.
- **2026-10-21 (W4, RS-1): The network lock refuses ambiguous URL authorities.** Decision: `Locks.network_allows()` (and the trainer bridge's loopback rule, through the new `Locks.is_loopback_url()`) refuse a URL whose authority (after "scheme://", up to the first "/") holds "@", "?", "#", "\", "%", whitespace or a control character, whatever `url_host()` reads. `url_host()` keeps its browser-style reading. *Alternatives:* make `url_host()` follow Godot's `String::parse_url` (two parsers can't be kept in step for every input, and the existing browser-style cases would flip). *Reason:* `HTTPRequest` cuts the authority only at "#" and "/" and then drops everything up to the first "@", so "http://127.0.0.1?@HOST/" reached HOST while locked (BRIEF 1, 7.5). The app's `scripted_config.gd` should use `Locks.is_loopback_url()` too (requests for lead).
- **2026-10-21 (W4, QT-5): `WlTrainerService._pending_change` removed.** It was only ever written: the release, the hand-back and the pending menu reset always set the rider up afresh from the current profile.
- **2026-10-21 (W4r2, NET-2): `LocalRider.resume_phase(index, elapsed_s)` for a rejoin into a running phase.** Decision: additive; GameHost calls it when a client enters a phase that already runs on the host. It forwards to `SafetyGovernor.resume_phase`, follows the MockTrainer's phase and clears the bands in the cool-down like `start_phase`. FIT laps: none when the rider already rides that phase or rode no phase of the plan yet (a restarted client's new FIT starts at the rejoin, BRIEF 3.6, so its first lap is that phase); a real phase change, the phase having moved on while the socket was down, laps as `start_phase` does so every interval keeps its lap (BRIEF 7.5). For a "course" phase the governor has no distance record of (a new rider), `estimate_course_distance` rides the speed model over the phase's course for `elapsed_s` at 75% FTP as P_eff, from that power's steady speed, with the rider's mass, difficulty and grade range, in 1 s steps. *Alternatives:* no lap ever (a socket rejoin after a phase change would lose that interval's lap); start the course at 0 (the trainer's road and the game's would be minutes apart); the game's own course position (game state the platform can't read). *Reason:* the estimate keeps a restarted rider near the right part of the course; it only steers SIM grade, which every 4.6.6 limit still bounds.
- **2026-10-21 (W4r2, SAF-1 range): every profile write is clamped, as loading is.** Decision: `WlSettings.save_profile()` first clamps the profile into `PROFILE_RANGES` (new static `clamp_profile(p)`, additive: a value out of range takes the nearest bound, NaN or infinity the default, each with push_warning), and `FtpTest` limits a valid result to the profile's 30-2000 W before showing and saving it. *Alternatives:* clamp only at load (W4r2: a Strava-imported or tested FTP below 30 W reached the rider stack, whose governor then kept its 200 W default); a setter on `RiderProfile.ftp_w` (a frozen contract field, and tests build out-of-range profiles on purpose). *Reason:* the profile is the source of the rider's watt basis (SAF-1), so it must hold only values the governor accepts.
