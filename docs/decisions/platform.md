# Decisions: platform (addons/wattlands/core)

Short ADRs for `WlSettings`, `WlApp`, `WlTrainerService`, `LocalRider`, `FtpTest` and `AutoloadLookup` (BRIEF 3.2, 3.5, 4.1, 4.6.9, 6).

- **2026-10-21: A missing settings file is a normal first run; a corrupt one warns.** Decision: a missing `profile.json` or `settings.json` gives the defaults silently; unparsable JSON or a non-object gives the defaults with `push_warning`; single values of the wrong type are dropped and numbers out of range clamped (`WlSettings.PROFILE_RANGES`), each with `push_warning`. `set_value` refuses a wrong type for a documented key with `push_error`; other modules may store their own JSON keys. Files are written to `<name>.tmp` and renamed over the old file. Alternatives: warn on missing files too; refuse to start on a corrupt file. Reason: every first launch and every test temp dir starts without files, and a hand-edited or half-written file must never block riding (an FTP of 0 or a weight of 5000 would reach the governor).
- **2026-10-21: `--strava-base=<url>` is a server root.** Decision: the API base becomes `<url>/api/v3` and the OAuth base `<url>/oauth` (a trailing `/api/v3` or `/oauth` is stripped first), for this run only, never saved; `--relay` likewise. Alternatives: use the URL as-is for both. Reason: the real Strava layout is `https://www.strava.com` + `/api/v3` and `/oauth`, and `tests/core/test_locks.gd` already uses `http://localhost:8899/api/v3/uploads`, so `server/mock_strava` can mirror the real paths. Rides reads `Settings.strava_api_base()` and `strava_oauth_base()`.
- **2026-10-21: Recent rooms and the last trainer live in `settings.json`.** Decision: `recent_rooms` (`{code, at, role}`, normalized code, `HOST`/`CLIENT`, newest first, one per code, at most 8, UTC `at`) and `last_device` are settings keys as the W0 stub documents; `TrainerService` copies `FtmsConnectionManager.last_device()` into `last_device` on every `trainer_ready`. `Paths.recent_rooms_path()` stays for compatibility; ble keeps its own `last_device.json`. Alternatives: separate files. Reason: one file, one loader, one corruption rule; the app shell reads both through `Settings`.
- **2026-10-21: One time base per rider.** Decision: `LocalRider` keeps its own platform time (integer microseconds, from 0 at each `setup()`), queues device samples when they arrive and processes them in the next `tick()` as copies stamped with that time. The governor, gestures, recorder and `Telemetry.t` all use it. Alternatives: pass the device's `sample.t` through. Reason: a MockTrainer or FtmsTrainer created before the rider (menus, reconnects) has another clock origin, and the governor's rescue, coasting and 3 s power rules must compare sample times with its own tick time.
- **2026-10-21: Raw trainer values in telemetry; the speed model drives the course.** Decision: `Telemetry.power_w`, `cadence_rpm` and `speed_kmh` are the trainer's, `distance_m` integrates the trainer's reported speed (the `Telemetry` contract and the recorder use that), and the speed model (P_eff on the applied SIM grade, 0 outside SIM) feeds only `SafetyGovernor.set_course_distance()`. A sample older than 3 s counts as gone (power, cadence and speed 0). W' balance steps every tick on the latest raw power; the recorder gets the latest values every tick and keeps 1 Hz itself. Alternatives: speed model speed in telemetry; W' and the recorder per sample. Reason: BRIEF 3.4 asks for W' every sim tick, per-tick feeding can't skip a second when notifications jitter to 1.1 s, and games integrate their own speed model (BRIEF 3.11).
- **2026-10-21: Exactly one ack per governor record.** Decision: every `directive_applied` record the governor emits is re-emitted by the rider and queued for `take_acks()` as `{id, kind, applied, clamped_by, refused, reason}`; `apply_directive()` queues the returned record itself only if the governor didn't emit during the call. Alternatives: ack only what `apply_directive` returns. Reason: course grades and other governor records also need acks, and the stub doc lets the governor both return and emit.
- **2026-10-21: A process-wide live-rider list for the exit paths.** Decision: `LocalRider.live_riders()` (weak references, filled by `setup()`, emptied by `shutdown()` and freeing) is what `WlTrainerService.shutdown_all()` walks on quit, window close, crash and tree exit. Alternatives: a register/unregister API on TrainerService that GameHost and GameSimRunner must call. Reason: BRIEF 4.6.9 must cover session and bot riders too, and a frozen GameHost stub can't be asked to call a new API in W1.
- **2026-10-21: The App boots only in the real app.** Decision: `WlApp._ready` defers `boot()` only when the SceneTree has no script; under GUT, `check_scripts.gd` or a tool's `-s` driver the App autoload stays in `boot` and never starts the trainer. A scripted peer (`--host`/`--join`) goes to `lobby` with `launch_options()`; the app shell drives it from there. Alternatives: boot always and stub Bluetooth in tests; an explicit `--no-boot` flag. Reason: no Bluetooth activity in tests (BRIEF 1) without asking every test runner to pass a flag.
- **2026-10-21: quit() order.** Decision: `goto("quitting")`, emit `quitting(code)` (the app shell saves rides and writes `--report` with the stack still up), save any ride still recording, `TrainerService.shutdown_all()` (SIM flat, then Stop), write a minimal scripted-peer report if `--report` was given and nobody wrote one, then quit, after 0.5 s of real time when a real trainer is connected so the safe commands can leave. A window close request runs the same path (auto-accept-quit is off in the real app); `NOTIFICATION_CRASH` and leaving the tree after boot shut the riders down at once. `--run-seconds` counts the App's own SimClock at `--sim-speed` and quits with `run_seconds_exit_code` (default 0). Alternatives: write the full report in the platform. Reason: the report's contents are session data the app shell owns; the harness still always finds a JSON file.
- **2026-10-21: The menu-time rider.** Decision: `TrainerService` builds its `LocalRider` (peer 1, profile slot in the saved scaling mode, solo, not recorded) as soon as a trainer exists, attaches it to the InputRouter, and ticks it on its own SimClock (`--sim-speed`) until `set_external_tick(true)`. Profile and scaling changes outside a session set the rider up again (a mock whose FTP, CP, W', cadence or weight changed is rebuilt); `hold_rider(true)` defers that, and releasing sets the rider up afresh. `EventBus.panic_requested` calls the rider's `panic()`. Switching trainers shuts the old rider down first. Alternatives: create the rider only for sessions. Reason: pedal gestures drive every menu (BRIEF 3.5), and the FTP test's cool-down must not be rebuilt by its own profile save.
- **2026-10-21: FTP test details.** Decision: `FtpTest` is pure logic (`start`, `step(dt, telemetry)`, `back`) plus `run_on(rider)`. The steps go up to min(1000 W, trainer max), at least one, at most 120. The power rule needs an ERG target above 0; the cadence rule ignores a cadence older than 3 s, so a trainer without cadence can finish. Rescue and coasting end at once and the cool-down phase starts in the same tick. The 10 s save countdown runs at the start of the cool-down, which continues; `back` cancels it. A test ended in the ramp-in or with `back` gives no result. Saving sets FTP, CP = FTP and `ftp_verified`. Alternatives: count down after the cool-down; save results from the ramp-in. Reason: the rider sees the result while still pedaling easily, and an estimate from a 50-65% ramp is meaningless.
- **2026-10-21: `AutoloadLookup` instead of autoload globals.** Decision: platform classes find `EventBus`, `Settings`, `TrainerService`, `Rides`, `InputRouter` and `App` through `/root` at run time and every class takes an injected instance first. Alternatives: name the autoloads as globals. Reason: the same classes run in GUT, in tools and in in-process multi-peer simulations, where each peer has its own bus (OWNERSHIP 3.1 C28).
- **2026-10-21: Handing ticking back makes the session rider the menu rider again.** Decision: `TrainerService.set_external_tick(false)` after `true` sets its rider up afresh (peer 1, the profile's slot, solo, no plan, no recorder, a fresh governor) and applies any profile or scaling change made during the session; while that rider's ride still records, the reset waits until `finish_ride()` (checked every menu step, `is_menu_reset_pending()`). Profile changes during a session wait for the hand-back instead of being dropped. `App.quit()` shuts the riders down before handing ticking back, so quitting never builds a menu rider and the shut-down governor keeps being ticked for its safe commands. Alternatives: leave the session's governor and plan in place in menus; reset at once and drop an unsaved ride. Reason: menus must ride free in SIM flat with solo gestures (coast never fires in ERG), and the results screen must still be able to save the ride.
- **2026-10-21: A ride is never lost to a rebuild.** Decision: `LocalRider.setup()` on a rider whose ride still records stops and saves that ride first (`push_warning`), and `TrainerService` does the same before switching trainers. Alternatives: drop it silently; refuse the setup. Reason: a saved ride is the one artefact a rider keeps (BRIEF 3.8), and the exit path already saves open rides.
- **2026-10-21: A new trainer object mid-session is rebound, not rebuilt.** Decision: `LocalRider.rebind_device(d)` keeps plan, phase, time, queues and recorder and calls `governor.setup(d)` again; `TrainerService` uses it when `trainer_ready` hands over a different device object while a GameHost ticks the rider (menus still rebuild the rider). Alternatives: free the rider and build a new one. Reason: the GameHost holds the rider; freeing it mid-session would crash the session. trainer-control's `setup()` must accept a second call that rebinds its controller.
- **2026-10-21: Setup clears a reused MockTrainer.** Decision: `LocalRider.setup()` clears the mock's cadence and power bands and sets its phase to -1. Alternatives: rely on the cool-down to clear bands. Reason: the app's `--mock-trainer` mock lives across sessions, and a session left before its cool-down would otherwise steer the next session's mock rider.
- **2026-10-21: FIT lap names are text.** Decision: lap names from phase labels and `lap_marker` labels go through `TranslationServer.translate` (strings keys become text, plain text passes through); unlabelled lap phases are `CORE_LAP_PHASE` ("Phase {n}") and the cool-down without a label `CORE_LAP_COOLDOWN`. Alternatives: the raw label. Reason: PL11 allows a strings key as a label (Tank), and Strava shows the lap name.
- **2026-10-21: settings.json holds JSON values only.** Decision: `set_value` refuses anything that doesn't survive JSON as itself (vectors, colors, non-string keys, NaN) with `push_error`; `set_last_device` first round-trips its dictionary through JSON (packed arrays become arrays). Alternatives: store whatever `JSON.stringify` makes of it. Reason: a value that comes back as a different type after a restart is a latent bug in another module.
- **2026-10-21: A dropped FtpTest lets go.** Decision: an `FtpTest` freed while driving a rider (the screen dropped it without `stop()`) puts the governor back on its normal profile and releases the TrainerService hold from `NOTIFICATION_PREDELETE`. Alternatives: rely on `stop()`. Reason: a forgotten hold would freeze every later profile change for the menu rider.
