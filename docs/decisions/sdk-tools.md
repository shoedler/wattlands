# Decisions: sdk-tools (template game, tools/run_game_sim, tools/new_game, docs/GAME_SDK.md)

Short ADRs for `src/games/_template/`, `content/_template/`, `assets/_template/`, `tests/games/_template/`, `tools/run_game_sim` (+ `.ps1`, `tools/sdk/`), `tools/new_game` (+ `.ps1`, `tools/lib/new_game.mjs`), `tests/tools/`, `tools/tests/new_game.test.mjs`, `tools/tests/run_game_sim.test.mjs` and `docs/GAME_SDK.md`.

- **2026-10-21: The template's string keys start with `_TEMPLATE_`.** Its id is `_template`, so the BRIEF 6 rule (upper-case id plus `_`) and the registry's computed defaults (`<ID>_OPT_<OPTION ID>`, `<ID>_CONTENT_<CONTENT ID>`) both give `_TEMPLATE_`, and the conformance test's prefix check passes without a special case. `tools/new_game` rewrites `_TEMPLATE_` and a bare `TEMPLATE_` to `<ID>_`. *Alternatives:* `TEMPLATE_` keys (the task text's spelling), which a generic prefix check would reject. *Reason:* one rule for every game, the template included.
- **2026-10-21: The template seats 1–4 riders with bots, one marker each.** BRIEF 3.6's "one rider pushes a marker" is read per rider. *Alternatives:* `max_players` 1. *Reason:* conformance runs every game at `min_players` and `max_players`, so a multi-rider template exercises HOST, CLIENT, snapshots and events, and a game scaffolded from it starts multiplayer-ready.
- **2026-10-21: Two contents.** `default` is BRIEF 3.6's session (a 300 s warm-up ramp 50 → 65 %, 180 s WORK at 75 % with `range_pct` [75, 80]); `short` is a 2-minute `e2e_content` inside the warm-up limits whose second phase is kind WARMUP (no offset, no nudge), like Siege's `drill`. `first_run_priority` is −1 so a scaffolded game never takes the first run by accident. *Reason:* `game.json` requires an `e2e_content`, and copies must be valid games.
- **2026-10-21: The template's effort nudge comes from the rules, never from Autopilot.** A +5 % "hill" at WORK elapsed 60 s for 30 s, inside `range_pct`, expiring back to the plan; boosts (Autopilot, surge, confirm, the HUD button) only change the marker's speed. *Reason:* BRIEF 3.5: Autopilot never changes effort targets.
- **2026-10-21: The 300-line budget counts the template's `.gd` files plus `game.json`** (296 lines now) and is checked by `tests/tools/test_template_size.gd`, which `tools/new_game` never copies, so scaffolded games may grow. Markdown files (README, HARDWARE_TEST) don't count.
- **2026-10-21: Template unit tests run on recording fakes; integration tests wait for the runtime.** `tests/games/_template/template_fakes.gd` stands in for the sinks and the GameHost's phase clock, so the module is tested in W1 while sdk-runtime builds in parallel. `tests/games/_template/integration/` drives the real registry, validator and `GameSimRunner`; each test is `pending` while those are W0 stubs and runs for real from W2. *Alternatives:* leave them failing until W2. *Reason:* the full suite stays green whatever the merge order, and nothing is weakened once the runtime exists.
- **2026-10-21: run_game_sim's logic lives in `GameSimCli` (`tools/sdk/game_sim_cli.gd`).** `tools/sdk/run_game_sim_main.gd` (extends SceneTree) only calls it on the first frame, once every autoload is ready. `GameSimCli` takes its flag parser, runner factory and environment reader as Callables, so GUT tests drive it with fakes. *Reason:* a SceneTree script can't be unit-tested in-process; the task asks for flag tests with a fake runner.
- **2026-10-21: run_game_sim checks flag names and syntax before `GameSimRunner.parse_args`.** It knows every BRIEF 3.6 flag, refuses unknown flags, missing values, repeats (only `--rider` repeats), a `--rider` count that is neither 1 nor `--players`, non-numeric values and non-JSON `--options`/`--player-options`, and an unreadable `--override` file, naming the flag. Values that need the manifest (option ranges, content ids) stay with `parse_args` and `setup`. *Reason:* a typo like `--player=2` must not silently run a default session; the checks are tested now, while `parse_args` is a stub.
- **2026-10-21: Exit codes 0 / 2 / 3 / 4.** 0 for a completed run with any `end_reason` (the report says which), 2 for bad flags or missing locks, 3 for setup errors (the validator's message included), 4 when the report can't be written; the Godot wrapper's 75 and 124 pass through.
- **2026-10-21: Relative `--report` and `--override` paths resolve against the caller's directory.** The wrappers pass `--caller-cwd=<pwd>`, because Godot changes its working directory to `--path` (checked with a probe: a relative path would land in the repo). MSYS turns `/c/...` into `C:/...` for Godot; PowerShell passes its provider path.
- **2026-10-21: The locks are checked twice.** The wrappers export `WATTLANDS_NO_HW_CONTROL=1` and `WATTLANDS_NO_NETWORK_INTEGRATIONS=1`, refuse `--allow-hw` and `--allow-network` and always add `--mock-trainer`; the entry script refuses to run unless both variables are 1 and `--mock-trainer` is present (BRIEF 1: the game-sim script passes `--mock-trainer` and refuses to run without it). *Reason:* starting the entry script by hand can't bypass the locks.
- **2026-10-21: `tools/run_game_sim.ps1` starts `tools/godot.ps1` in its own `powershell -File` process** through `Invoke-WattlandsNative`. *Alternative:* `& godot.ps1 @args`. *Reason:* `-File` passes every argument untouched (a bare `--`, JSON with quotes); tested with `--options` and `--player-options` JSON from Node.
- **2026-10-21: `--echo-args`.** Prints the flags exactly as the entry script would pass them to `parse_args` (after path resolution) and the lock values, then exits 0 without running. It makes the whole wrapper → Godot chain testable without the runtime and helps debug quoting.
- **2026-10-21: run_game_sim points `Paths.user_dir()` at a fresh temp dir for the run and removes it afterwards** (`isolate_user_dir`), on top of the runner's per-slot temp profiles (OWNERSHIP SIM7). *Reason:* nothing in a simulation can touch the user's real profile, progress or rides.
- **2026-10-21: new_game never refuses over the docs fragments (OWNERSHIP C17).** Only `src/games/<id>/`, `content/<id>/`, `assets/<id>/`, `tests/games/<id>/` and `.github/workflows/game-<id>.yml` (which it writes) trigger the refusal; `docs/{decisions,credits.d,changelog.d}/<id>.md` are created only when missing and never overwritten. *Alternative:* the task text lists the fragments among the refusal targets. *Reason:* Siege's and Tank's G0 may write `docs/decisions/<id>.md` before running `tools/new_game`; C17 resolves this conflict and the task's test list cites it.
- **2026-10-21: new_game's rewriting rules match at word starts only,** in this order: `_TEMPLATE_` → `<ID>_`, `TEMPLATE_` → `<ID>_`, `_template` → `<id>`, `Template` → `<Id>` (PascalCase of the id: `big_fish` → `BigFish`), `template_` → `<id>_`, applied to file contents and names. *Reason:* `test_template_rules.gd` must become `test_<id>_rules.gd` (a plain `_template` replacement gave `testdemo_rules.gd`), and helper names like `_is_template` must survive. The title becomes the id in words (`Big Fish`).
- **2026-10-21: new_game skips `.uid`, `.import` and `.translation` files** (all generated by the import) and strips `uid="uid://..."` attributes from `.tscn`/`.tres`. *Reason:* copied uids would collide with the template's; a copied `.translation` would hold the template's keys until the next import. Exit 1 for a refusal, 2 for a usage error (no id or a bad id), nothing written in either case; writes are planned in memory first and rolled back if one fails.
- **2026-10-21: new_game writes the game's CI workflow** (`tools/run_tests --only=gut --gdir=res://tests/games/<id>`, the script check, Godot 4.7.2 on ubuntu-latest), as OWNERSHIP TL1 recommends; the game session owns and extends it.
- **2026-10-21: GAME_SDK.md marks other modules' details with "W2:".** Where the doc must name a value another W1 builder decides in parallel (the run_game_sim report keys and flag defaults against `tests/sdk/test_sim_report.gd`, HudLayer's CanvasLayer layer and Theme path, widget minimum rects, `intervals`/`noise` profile keys, the fit_check and e2e JSON schemas, the Workout examples), it says so instead of guessing; the lead resolves them in W2.
- **2026-10-21 (hardening review): run_game_sim exits 5 when Godot logged a SCRIPT ERROR during the run.** GDScript ends a function that hits a script error and returns its type's default, so `GameSimCli.run()` (or a broken `setup()`) could hand back 0 and the process would exit 0 with no report or a wrong one (checked with a probe). `GameSimCli.main()` registers a `Logger` (`OS.add_logger`, Godot 4.5+) that counts `ERROR_TYPE_SCRIPT` only, and turns an exit 0 into 5, naming the first error; any other non-zero code wins, and the report is still written when the run got that far. `push_error`/`push_warning` never count: they report bad input. *Alternatives:* exit 0 and only print a warning (a broken game would pass its simulation matrix); detect only an aborted `run()` (misses errors inside the session). *Reason:* BRIEF 7 treats any SCRIPT ERROR as a failure; the task's "exit 0 for any end_reason" still holds for clean runs.
- **2026-10-21 (hardening review): each run first deletes the report and its `fit/<stem>_slot<n>.fit` files at its `--report` path.** *Alternatives:* leave old files (a run that fails at setup, after a tuning change in a G2 balance loop, would leave the previous run's report for `check_sims.mjs` to pass on). *Reason:* a failed run must never look like a passed one. `--echo-args` deletes nothing; only files matching that exact pattern are touched.
- **2026-10-21 (hardening review): the wrappers pass `--mock-trainer=erg`, not a bare flag.** CmdLine reads a bare flag as the value "true", and autoloads that honour `--mock-trainer=<profile>` (TrainerService, App) would see an invalid spec in a run_game_sim process. `erg` is a valid profile; the riders still ride their own `--rider` profiles.
- **2026-10-21 (hardening review): run_game_sim checks slot lists against the slots** (`--players` plus `--bots` at most `Wl.MAX_SLOTS`; `--autopilot`/`--haptics-off` slots below `--players`; at most one `--ftp` value per slot and one `--player-options` object per human slot) and hands `--unverified` to `parse_args` as a bare flag (`--unverified=false` drops it). *Reason:* these need no manifest, so the CLI can name the flag before any Godot work.
- **2026-10-21 (hardening review): new_game refuses ids whose class names already exist.** Two ids can share a class prefix (`big_fish` and `big__fish` give `BigFish`, `a_1b` and `a1b` give `A1b`) and the id `template` gives `TemplateGame`; the target-path check misses all of these. It scans `class_name` lines under `addons/`, `src/`, `tests/` and `tools/` (skipping `.godot`, `build`, `node_modules`, ...). *Alternative:* forbid `__`, trailing `_` and digit-led segments in ids (narrower than OWNERSHIP TL1's `^[a-z][a-z0-9_]*$`, and still misses `template`).
- **2026-10-21 (hardening review): the template validates every content phase at load** (kind, never COOLDOWN, `target_pct`, `duration_s` > 0, `label`, optional `ramp_to_pct`) and every tuning number, so bad content or a bad `--override` patch is refused with a reason instead of a script error in `build_effort_plans`. Numbers may be JSON floats, GDScript ints or numeric strings. The package test's wall-clock/global-RNG scan skips views, which may seed their own cosmetic RNG from `ctx.seed` (Fishing 3.5); the template still has 298 lines.
- **2026-10-21 (W2): GAME_SDK.md's W2 placeholders are filled from the merged code, and the report section follows `build_report()`.** The report table now lists the keys `GameSimRunner.build_report()` writes and `tests/sdk/test_sim_runner.gd` pins (`trace` with rows `{t, game_t, phase, ...}`, events `{t, pt, type, ...}` with game events under `game_event`, `snapshots` `{seq, tick, sha256, bytes}`, `clients`, `unlocks`, ...); the W1 draft had `traces` and other guessed keys. `--sim-speed` is documented as recorded but not pacing headless runs (they always step as fast as they can), and SOLO report runs as measuring snapshots. *Alternatives:* rename the runner's keys to the draft's. *Reason:* qa's scenarios, Workout's sims and the runner's tests already read the code's keys; the code is the contract's final word.
- **2026-10-21 (W2): `tools/run_game_sim --game=_template` runs the template.** The template is never listed, so the GameRegistry autoload refused it (exit 3, and `tools/tests/run_game_sim.test.mjs`'s real session failed once the W2 runtime merged). For `--game=_template` the CLI hands `GameSimRunner` a private registry with the installed games plus the template (as the conformance test loads it), freed after the run; it is still never listed anywhere. *Alternative:* point the Node test at Workout. *Reason:* the template is the game every session studies first; running it through the real tool is part of that.
