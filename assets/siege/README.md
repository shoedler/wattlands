# Siege assets

This folder is the game's `assets/<id>/`. Everything in it is made by our own code; nothing is generated by an outside service or downloaded.

## `bake/`: the baked 2D art

Written by `node src/games/siege/art/bake.mjs` from the same scene as the approved mock (`src/games/siege/art/*.mjs`, a Node CPU rasterizer). It takes about 3.5 s. Commit the PNGs with the `.import` files Godot creates for them (`tools/godot.sh --headless --path . --import`).

| File | What it is |
| --- | --- |
| `world.png` | The static world at 960 x 540 art pixels: everything that never moves or takes a rider's hue, with sun shadows, AO, outlines, glow and the grade. No tilt-shift, vignette or haze (the view's screen shader adds those). |
| `world_depth.png` | Per pixel of `world.png`: depth x + y + z in 16 bits (R high byte, G low byte) as `(depth - offset) * scale`, 0 for the sky; B is the sun (255 lit, 0 in shadow). |
| `atlas_<n>.png` | The dynamic parts' frames (wheels, routes, shafts, stations, gate, tar, pads, enemies, effects, projectile pixels). Rider-hue pixels are a magenta key ramp the view recolours to the slot's ramp or the part's idle material; a dark halo pixel is black at `halo_alpha`. |
| `atlas_<n>_depth.png` | Each frame pixel's depth relative to the frame's anchor, 16 bits in R and G (`rel * scale + zero`), same layout as its atlas. |
| `manifest.json` | The generator and `bake_version`, the depth encodings, the key ramp, the slot and idle ramps, the atlases, and every part: anchor, layout and frames (atlas, rect, anchor pixel offset). |

`SiegeBakeBank` (`src/games/siege/view/v2/siege_bake_bank.gd`) loads it; `docs/GAME_SDK.md` section 18 has the 2D kit around it.

### Changing the art

1. Edit the rasterizer (`scene.mjs`, `life.mjs`, `shade.mjs`, `raster.mjs`, `sprites.mjs`, `bake.mjs`). Keep `node src/games/siege/art/mock.mjs` rendering the approved frame unless the art itself is meant to change.
2. Bump `BAKE_VERSION` in `bake.mjs`.
3. Run `node src/games/siege/art/bake.mjs`, then the import, and commit the files.

`node src/games/siege/art/bake.mjs --check` exits non-zero when the committed manifest's `bake_version` differs from the code's or a listed file is missing. `tests/games/siege/view2/bake_check.test.mjs` runs it (and `export_map.mjs --check`) in the node step of `tools/run_tests`, and `tests/games/siege/view2/test_siege_bake_bank.gd` checks the version from GUT.

## `hud/`: the HUD's letter and icons

Written by `node src/games/siege/art/hud_bake.mjs` from the mock's own code (`hud_font.mjs`, `hud_parts.mjs`), so the art and the game match. `hud_atlas.png` holds every face (LABEL, BODY, LINE, NUM, KEY, KEY28, KEY36), the icons and the slot shapes, white where a pixel takes the tint; `hud_atlas.json` holds the rects and glyph metrics. Commit the PNG, its `.import` and the JSON. `--check` fails when they differ from what the code makes; `tests/games/siege/hud/hud_bake_check.test.mjs` runs it.

## Sound

Every sound is synthesized at runtime with `Sfx.synth` (`src/games/siege/audio/siege_audio.gd`); coins and the Breach boom are the platform's built-in `coin` and `boom`. There are no sound files. Credits: `docs/credits.d/siege.md`.
